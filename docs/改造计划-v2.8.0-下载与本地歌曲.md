## 一、一句话说清这个改动

给播放器加一条**完整的离线链路**：把 B 站的音频**下载到本地**，用一个「下载管理」页面看进度、管任务，
再用一个「本地歌曲」页面把**下载来的歌和从硬盘导入的歌**放在一起当曲库播。

下载入口一共 4 个（单曲行内、播放条、歌单/我喜欢批量、合集选集行内），下载位置**首次弹窗选择、之后记住**。

**核心原则：下载的东西必须能原样播、能找得到、能删得掉；不污染用户的音乐文件夹。**

## 四、数据模型

### 4.1 新增的字段（`app.js` 的 `DB`，`store-migrate.js` 的 `DEFAULT_DATA`）

```js
DB.local = [
  {
    id: 'loc_1a2b3c',        // 稳定 id，列表 key 用
    path: 'D:\\Music\\浅影阿 - 距离隔不开.m4a',  // 绝对路径（唯一键）
    title: '距离隔不开',
    author: '浅影阿',
    cover: '9f3a....jpg' | '',   // 相对 coversDir 的文件名；没有就空
    duration: 213,           // 秒；导入的未知填 0，播放时回填
    size: 4211000,           // 字节；未知填 0
    src: 'download' | 'file' | 'folder',  // 来源，用于界面提示
    key: 'BV1xx:39243287210' | '',  // 下载来的才有：bvid:cid，用于「已下载」标记与去重
    bvid, cid,               // 下载来的才有：重下时能直接排进队列
    addedAt: 1760400000,
  }
]
```

> **★ 实施时改掉的**：这一节原来还列了一个 `DB.downloads`（任务数组）要进 `neko-data.json`。
> 实际没这么做 —— 那个文件已经 6MB，而下载进度**每 300ms 变一次**，写进去等于每 300ms
> 序列化并落盘 6MB，界面会直接卡住。任务状态改由**主进程单独存**
> `<userData>/downloads.json`（攒 1.5 秒写一次 + 退出时强制写一次，`.tmp` + `rename` 原子替换）。
> 于是 `neko-data.json` 里**没有** `downloads` 这一项，`store-migrate.js` 也**不许**补它 ——
> `verify.js` 第 56 类有一条反向断言专门盯着这件事。

任务记录的形状（存在 `downloads.json` 里，`downloader.js` 自己管）：

```js
{
  id: 'dl_7f2e91',
  key: 'BV1xx:39243287210',   // 去重键
  bvid, cid, page, title, author, cover, duration,
  status: 'queued' | 'downloading' | 'paused' | 'done' | 'failed',
  received: 0,      // 已写入字节（续传用）
  total: 0,         // Content-Length，未知为 0
  file: '浅影阿 - 距离隔不开.m4a',  // 相对下载目录的文件名
  coverFile: '',    // 相对 coversDir 的封面名（saveCover 打开时才有）
  error: '',        // 失败原因
  createdAt, finishedAt,
}
```

`speed`（字节/秒）**只存在内存里**（`runtime` 那张表），不落盘 —— 它是每 300ms 重算的瞬时值。

### 4.3 迁移（`src/store-migrate.js`）

按该文件开头的**铁律**（只许补、不许删）新增：

```js
d.local = Array.isArray(d.local) ? d.local : [];
s.download = Object.assign({}, DEFAULT_DOWNLOAD, old.download || {});
// concurrent 夹到 1~4；三个开关只认"显式 false"；dir 存在性校验见下
```

> ⚠️ 同时要**校验 `dir` 是否还存在**（像 `bg.file` 那样 `fs.existsSync`）：
> 目录被删/换电脑后 `dir` 要降级成 `null`，否则下载会一直失败在"目录不存在"。
>
> ⚠️ 而 `concurrent` / 三个开关的**夹范围**在 `store-migrate.js` 和 `app.js` 里各有一份
> （前者管"打开老存档"，后者管"设置面板里改"）。两份默认值必须逐字一致，
> 所以 `app.js` 那边也抽了一个 `DOWNLOAD_DEFAULTS` 常量 —— `verify.js` 第 56 类会逐项对。

### 4.4 曲目身份：让本地歌融入现有体系（关键改动，只动一个函数）

`app.js:679-681` 的 `sameTrack` 是全局的"是不是同一首"判定（收藏、历史、队列、正在播放高亮全靠它）。
本地歌没有 bvid/cid，所以扩一条：

```js
function sameTrack(a, b) {
  if (!a || !b) return false;
  // 本地歌用路径当身份证（它没有 bvid/cid）
  if (a.localPath || b.localPath) return !!a.localPath && a.localPath === b.localPath;
  return a.bvid === b.bvid && String(a.cid) === String(b.cid);
}
```

渲染时把 `DB.local` 的条目**适配成 track 形状**（`{ localPath, title, author, cover, duration, bvid: null, cid: null }`），
于是 `trackRow` / `trackListHTML` / 收藏 / 历史 / 队列**全都不用改**。

## 五、主进程实现

### 5.1 下载引擎（新文件 `src/downloader.js`）

> 为什么单独一个文件：和 `win-mini.js` / `bg-protocol.js` / `store-migrate.js` 同样的理由 ——
> `main.js` 没法被测试 require，抽出来才能离线实测（含打桩 `net.fetch`）。

导出：

```js
createDownloader({ dir, coversDir, onUpdate, onProgress, getAudioUrl, referer, userAgent })
  → { add(tracks), pause(id), resume(id), retry(id), cancel(id),
      remove(id, deleteFile), clearFinished(), setDir(dir), list(), stats() }
```

下载一个任务的流程：

1. `getAudioUrl(bvid, cid)`（复用 `bili.getAudioUrl`，`bilibili.js:417-437`）拿真实地址
2. 目标文件名 = `sanitize(author + ' - ' + title) + '.m4a'`；重名则 ` (2)` ` (3)`
3. **续传**：`received > 0` 时带 `Range: bytes=<received>-`
   - 回 `206` → 追加写（`fs.createWriteStream(part, { flags: 'a' })`）
   - 回 `200` → 服务器不支持 Range → 截断重下（`flags: 'w'`）
4. 写的是 `xxx.m4a.part`，**完成后才 `rename` 成 `xxx.m4a`**（原子，不留半成品）
5. 封面：`saveCover` 开着且有 `track.cover` 时，抓一次图存到 `coversDir/<key>.jpg`
6. 写 `DB.local` 条目（`autoAddToLocal` 开着时）
7. 进度：每 300ms 汇总一次（不是每个 chunk 都发），避免 IPC 洪水

**并发**：队列 + 最多 `concurrent` 个同时跑；`pause` 用 `AbortController` 中断但**保留 `.part`**，`resume` 从断点续。

**关闭软件时**：`downloading` 的任务在退出前统一改写成 `paused` 并落盘（下次打开可继续）。

### 5.2 `local://` 协议（新文件 `src/local-protocol.js`）

> ⚠️ **这是本次改动最需要小心的地方** —— 它把任意本地文件暴露给渲染进程。
> 安全边界必须靠**白名单**，不能靠路径拼接。

两个入口：

| URL | 服务什么 | 校验 |
|---|---|---|
| `local://get?p=<encodeURIComponent(绝对路径)>` | 音频文件 | 该路径必须**精确等于** `DB.local` 里某条的 `path`（Set 精确匹配，不做前缀/规范化猜测） |
| `local://cover?f=<文件名>` | 封面图 | 文件名必须是纯 `[\w.\-]+`，且拼出的绝对路径必须仍在 `coversDir` 内（照抄 `bg-protocol.js:53-60` 的两道闸） |

- 两者都支持 **Range**（拖动进度条、边下边播要靠它），实现照搬 `bg-protocol.js:73-104`
- 白名单缓存：主进程在 `store:load` / `store:save` 时刷新一个 `Set`，请求时查内存，不每次读盘
- 白名单为空 → 一律 403

## 七、安全边界（本次最需要守住的三条）

1. **`local://` 只认白名单**。`DB.local` 里的绝对路径集合是唯一的放行依据；
   绝不用「拼接 + startsWith」这种可以被 `..` 绕过的写法（`bg-protocol.js` 那两道闸是给固定目录用的，
   我们这里是任意路径，必须精确匹配）。
2. **`shell:open` 的既有红线不动**（`main.js:795-802` 只放行 http/https）。
   新加的 `download:openDir` / `download:reveal` 只接受**下载目录内的路径**，同样要校验，
   不能变成"让网页打开任意本地路径"的后门。
3. **文件名清洗**。Windows 非法字符 `\ / : * ? " < > |` 与首尾空格/点全部替换，
   总路径长度控制在 240 字符以内（含目录），避免超长路径写失败。

## 八、错误处理与边界情况

| 情况 | 表现 |
|---|---|
| 从没选过下载目录 | 首次点下载 → 弹系统选目录框 → 取消则整体放弃，提示「还没选下载位置」 |
| 目录被删 / 移动 | `store:load` 时校验，降级成 `null`；下载时提示「下载目录不见了，请重新选择」 |
| 该视频没有音频流（会员/版权） | 任务标 `failed`，原因用 `bilibili.js:425` 那句现成文案 |
| 未登录 / Cookie 过期 | 复用现有 `reason` 机制，提示「去设置里填 Cookie」 |
| 已下载过（同 `bvid:cid` 且文件在） | `skipExisting` 开着 → 直接跳过，提示「N 首已存在，已跳过」 |
| 磁盘写失败 / 空间不足 | 任务 `failed`，保留 `.part` 供重试；提示里带系统错误信息 |
| 下载中关掉软件 | 退出前统一写成 `paused`，下次打开显示「已暂停 · 62%」可继续 |
| 导入的文件夹里有几万个文件 | 扫描限深 + 限量（上限 5000 个），超了提示"只导入了前 5000 个" |
| 导入的文件被删/改名 | `local:list` 时 `fs.existsSync` 检查，标 `missing`，列表置灰 + 顶部黄条 |
| 本地歌的时长未知 | 播放时从 `<audio>` 的 `duration` 回填，写回 `DB.local` |

## 十三、风险与实施顺序

### 13.1 风险

| 风险 | 应对 |
|---|---|
| `local://` 白名单写错 → 任意文件读取 | `test-round19.js` 把「白名单外必须 403」当作**头号断言**；实现时先写测试再写代码 |
| 续传时服务器回 200 而非 206 → 文件损坏 | 显式判状态码，非 206 一律截断重下；测试用打桩覆盖这条 |
