# 第一部分：动态背景（缩放 + 性能 + 改名）

## 1.0 先说结论

| 你现在看到 | 改完以后 |
|---|---|
| 窗口化时视频被裁成"只看到左上角一块"，人物跑到屏幕外；全屏才正常 | 视频**永远等比铺满窗口**，怎么拉都正常 |
| 一开视频背景，GPU 直接 60% | **大幅下降**（真机实测数字见 1.4；毛玻璃不再对会动的画面每帧重算） |

## 1.1 逐条对账（含实测证据）

### 1.1.1 视频不随窗口缩放 —— 已定位根因，并**实测复现**

**现状**：`src/ui/style.css:147-153`

```css
.bg-layer #bgVideo {
  position: absolute;
  inset: 0;            /* ← 就是这里不管用 */
  object-fit: cover;
  z-index: -1;
  display: none;
}
```

**根因**：`<video>` 是**替换元素**（replaced element）。按 CSS 规范，对**绝对定位的替换元素**，
当 `width/height` 是 `auto` 时，取值是**元素的内在尺寸**（= 视频真实分辨率），
`inset: 0` 里的 `right` / `bottom` 会被**直接忽略**。
所以 `inset:0` 那套"撑满父容器"的写法**只对普通元素有效，对 `<video>` 无效**。

**实测证据**（一次性脚本，真跑 Electron，三种窗口尺寸各量一次）：

| 窗口内尺寸 | `.bg-layer` 盒子 | `#bgVideo` 盒子 | 结论 |
|---|---|---|---|
| 1181 × 761 | 1229 × 809 | **300 × 150** | 不随窗口变 |
| 802 × 602 | 850 × 650 | **300 × 150** | 不随窗口变 |
| 1500 × 900 | 1548 × 948 | **300 × 150** | 不随窗口变 |

（`300×150` 是浏览器给"还没有内在尺寸的 `<video>`"的默认值。换成真实素材，`videoWidth/videoHeight` 是多少，
元素盒子就是多少 —— 1920×1080 的素材，元素盒子就是 **1920×1080**，锚在左上角 `(-24,-24)`。）

**完整解释了你看到的现象**：窗口 1180×760 时，一个 1920×1080 的盒子只有**左上角一块**露在窗口里
（= 第一张截图里"被放大、人物跑到右下角外"）；窗口拉到 ≥1920×1080（全屏）时盒子正好盖住窗口
（= 第二张截图"正常"）。

> **图片背景一直是好的**：它走 `background-size: cover`（CSS 背景图，不是替换元素），不吃这个坑。

### 1.1.2 GPU 60% —— 四个原因，其中一个是主因

**根因 A（主因）：4 个常驻"毛玻璃"面板压在会动的画面上**

| 行号 | 选择器 | 面积 |
|---|---|---|
| `style.css:192` | `.titlebar` | 整宽 |
| `style.css:232` | `.sidebar` | 整高 |
| `style.css:329` | `.topbar` | 整宽 |
| `style.css:532` | `.player` | 整宽 |

`backdrop-filter` 的含义是"**把我背后那块画面实时糊一遍**"。
背后是**静态图片**时，糊一次就缓存住了，几乎不花钱；
背后是**视频**时，**每一帧都要重新采样 + 重新模糊**这 4 块大面积区域。
60fps 下 ≈ 每秒 **240 次大区域高斯模糊**。这就是 GPU 被打满的主因。

**根因 B**：`style.css:121` `.bg-layer { filter: blur(var(--bg-blur)); }`，而 `#bgVideo` 是它的**子元素**。
等于"先解码一帧 → 整层（含视频）糊一遍 → 再合成"。模糊滑杆 > 0 时每帧都做。

**根因 C**：缩放 bug 的副作用 —— 视频按 1920×1080 渲染进 1229×809 的层，**多算近 1 倍像素**。修完 P1 自动消失。

**根因 D**：只有 `visibilitychange`（= **最小化**）会暂停。
**窗口失焦**（切到浏览器，窗口还露着）不停；**被别的窗口盖住**不停；**打开设置面板**（大遮罩盖在视频上）不停。

### 1.1.3 命名

`index.html:473` 附近分区标题是「背景（图片 / 视频）」，`app.js` 的 `bgHint` 写「自定义视频背景 ✓」，
README / CHANGELOG 里也全是「视频背景」。
**改**：用户可见处统一改成 **「动态背景」**。
**内部字段名 `settings.bg.kind` 不动** —— 改了要写存档迁移，不值当，用户也看不见。

## 1.2 市面做法调研

**开源动态壁纸 Lively Wallpaper**（GitHub `lively-community/lively`，官方 Performance 文档）：

- 视频壁纸**走 GPU 的专用视频解码硬件**（任务管理器里显示 `Video Decode` 引擎）
- **"不管什么类型的壁纸，只要全屏应用/游戏在跑，Lively 会完全暂停壁纸播放"**
- 另外几档暂停策略：**其它应用获得焦点就暂停** / **电池供电就暂停** / **屏幕被窗口盖住 95% 就暂停**（网格覆盖检测）
- 它文档里还提醒：任务管理器里的 GPU% 是**相对当前频率**的，显卡低频待机时百分比会显得虚高

**动态背景其实分三类**：

| 类型 | 代表 | 开销 |
|---|---|---|
| 静态图 + 缓慢缩放/视差 | Windows 聚焦、macOS 动态壁纸 | 极低 |
| **低分辨率循环视频** | Lively、Wallpaper Engine | 中（靠硬解） |
| WebGL / Canvas 着色器 | Wallpaper Engine 的 Scene 壁纸 | 高（但可降帧） |

**关于"视频转 GIF"—— 不建议，反而更贵**：

- GIF 只有 **256 色**、无半透明 → 星空 + 人物渐变会出色带
- GIF **没有硬件解码**，靠 CPU 逐帧解 → 现在的 **GPU 60% 会变成 CPU 飙升**
- 同画质下**体积是 mp4 的 5~20 倍**
- Lively 这类工具**全都用视频而不是 GIF**，就是这个原因

**真正省显卡的方向**（按性价比）：① 别让毛玻璃每帧重算 ② 窗口不在前台就停 ③ 源视频压到 720p / 24~30fps

## 1.3 方案

### P1 修缩放（1 行 CSS，但这是主 bug）
`style.css:147-153` 的 `#bgVideo` 补 `width: 100%; height: 100%;`。

### P2 把"模糊"从视频身上摘掉（治根因 B）
- `.bg-layer` **不再挂 `filter`**
- 新增只管图片的子元素 `<div class="bg-image" id="bgImage">`：
  `background-image: var(--bg-image); background-size: cover; filter: blur(var(--bg-blur));`
- `#bgVideo` 变成它的**兄弟节点**，不参与模糊
- `app.js:237` 的 `layer.style.filter = ...` 挪到 `#bgImage`
- 设置面板：「背景模糊」滑杆在**背景是视频时置灰 + 提示**
- **图片背景行为完全不变**

### P3 动态背景时自动降毛玻璃（治根因 A，最大收益）
- `<body>` 加类 `perf-lite`
- CSS 里在 `body.perf-lite` 下，把 4 个面板的 `backdrop-filter` 设成 **`none`**，
  同时把 `background` 透明度调实一点（`--glass-alpha` +0.12 左右），观感上仍是"磨砂面板"
- **只在 `settings.bg.kind === 'video'` 时加这个类**（图片不动，毛玻璃不花钱）
- 设置项 **「动态背景时降低毛玻璃（省显卡）」默认开**，可关

> 为什么用 `none` 而不是 `blur(0px)`：`blur(0px)` 仍会触发"把背后画面拷进纹理"，真正省下的是 `none`。会在离屏实测里量 computed 值验证。

### P4 补齐"该停就停"的规则（治根因 D）
- **窗口失焦**（`blur` / `focus`）→ 暂停 / 恢复
- **打开任何遮罩**（设置面板 / 歌单选择 / 合集面板 / 队列抽屉）→ 暂停
- 保留现有 `visibilitychange`
- 设置项 **「窗口不在前台时暂停动态背景」默认开**

### P5 提示源视频规格（不做自动转码）
- 选视频时读 `videoWidth/videoHeight`：**宽度 > 1920** 时提示「建议用 720p/1080p，更省显卡」
- **不做**自动转码（要带 ffmpeg，安装包大几十 MB）
- **不做**帧率探测（`requestVideoFrameCallback` 估算在刚加载时容易误判，收益低）

### P6 改名「动态背景」
- `index.html` 设置面板分区标题、`app.js` 的 `bgHint`、`README.md`、`CHANGELOG.md`
- 存档字段一律不动（零迁移不变）

## 1.4 第一部分的验证

**A. 静态自检**（`verify.js` 38 → **41 类**）
1. `#bgVideo` 的 CSS 含 `width:100%` 和 `height:100%`
2. `.bg-layer` 不含 `filter:`；存在 `.bg-image` 且它带 `filter: blur(var(--bg-blur))`
3. 4 个面板在 `body.perf-lite` 下 `backdrop-filter: none`；`applyAppearance()` 按 kind 切 `perf-lite`
4. 用户可见文案里不再出现「视频背景」

**B. 离屏实测**（新增 `test-round8.js`）

| # | 测什么 | 判据 |
|---|---|---|
| 1 | **缩放（核心）** | 窗口 1180×760 / 800×600 / 1500×900 下，`#bgVideo` 盒子 == `.bg-layer` 盒子（±2px） |
| 2 | 模糊隔离 | `.bg-layer` computed `filter === 'none'`；`.bg-image` 的 `filter` 含 `blur` |
| 3 | 毛玻璃降级 | `kind=video` 时 4 面板 computed `backdrop-filter === 'none'`；`kind=image` 时 **不等于** `none` |
| 4 | 暂停规则 | `window.blur` → `paused===true`；`focus` → `false`；开设置遮罩 → `true` |
| 5 | 改名 | 设置面板标题/提示是「动态背景」，**不再**出现「视频背景」 |
| 6 | 图片背景不受影响 | `kind=image` 时 `.bg-image` 有背景、`#bgVideo` 隐藏且 `paused` |

**C. 回归**：41 类 + `test-ui`(17) / `test-collect` / `test-persist` / `test-round6`(36) / `test-round7`(7) 全绿

**D. 性能（说清楚测不到什么）**
- **沙箱没有真实 GPU**（软件光栅），**测不了任务管理器那个 GPU%**
- 能测的是**渲染帧时间**（`requestAnimationFrame` 采样 3 秒帧间隔），只能当**相对指标**
- **真实 GPU% 要你本机验**：改完开任务管理器对着同一段视频再看一次，和截图里的 60% 比。**这一步我不会替你下结论。**

## 2.1 回答"更新日志该放哪"

**三处分工不同，都要有**：

| 放哪 | 是什么 | 给谁看 | 现在 |
|---|---|---|---|
| `CHANGELOG.md` | **完整**的逐版本变更记录 | 想查"某版具体改了什么"的人 | ✅ 有，很细 |
| **GitHub Releases** | 每个版本的**发布页**，可挂安装包，自动列"自上一版以来的提交" | 想**下载**某个版本的人 | ❌ 无 |
| `README.md` | 只放**最近一版摘要**（3~5 条）+ 跳转链接 | 第一次来的访客 | ❌ 无 |

**一句话**：README 放「**最近**发生了什么」，CHANGELOG 放「**所有版本**发生了什么」，Releases 放「**这一版能下载什么**」。

**Releases 不是用来读历史的**（翻起来累，且没有导航）。核心价值是 ① 挂安装包 ② 给版本打节点 ③ 让 `.../releases/latest` 永远指向最新版。
你要的"每次更新在主页有体现" = **README 摘要 + CHANGELOG 全记 + 发一版 Release**，三件一起做。

# 第五部分：已知取舍

1. **动态背景 + 降毛玻璃 = 面板会显得"实"一点**（不再实时透视背后在动的画面）。拿观感换显卡，做成开关，默认开。
2. **不做 GIF 转码**：更费 CPU、更糊、文件更大。
3. **不做源视频自动转码**：要带 ffmpeg，安装包大几十 MB；改为提示用户自己压到 720p/30fps。
4. **沙箱测不了真实 GPU%**：只能给相对帧时间，真实数字要你本机任务管理器对照。
5. **不做英文版 README**：应用 UI 是中文的、面向中文用户；高星项目做英文是因为面向全球。
6. **不做 exe 直链**：Release 还没发；发完之后才能挂直链。
7. **GIF 演示尽力而为**，做不出就用 4 张静态图。
8. **改名只改用户可见文案**：存档字段不动，零迁移不变。
