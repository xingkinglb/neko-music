# 改造计划：播放队列跟随来源 + 合集单曲开关 + 播放模式合并 + 详情返回

> 目标：把这次提的 5 个问题一次处理干净。前 4 条其实是**同一个根**——
> 播放队列里的「合集」一直只是**一行**（只代表第 1P），展开面板里的上百集从来没有进过队列，
> 于是"顺序播放到合集只播第一首就跳过"和"合集里没法挑着听"都是这个根长出来的枝。
> 这份文档是**动手前的施工图**，确认后再改代码。

---

## 〇、先说结论：这一版会变成什么样

| 你现在看到 | 改完以后 |
|---|---|
| 搜索结果行尾「ⓘ详情」点进去 → 只有解析结果，**回不去** | 详情页左上角有「‹ 返回」，回到你原来那一页（连滚动位置一起还原） |
| 队列里显示的来源名是**上一次**播的那个列表 | 队列来源 = **你点播放的那个界面**（我喜欢 / 某个歌单 / 搜索结果 / UP 主页 / 发现 / 解析页） |
| 在「我喜欢」听歌时删收藏，正在播的队列也跟着少一首 | 队列是启动播放那一刻的**快照**，源列表后续怎么改都不动正在播的这一份 |
| 合集在队列里是**一行**，播完第 1P 就跳走 | 合集按你勾选的曲目**摊平成多行**进队列，一集接一集播完再走下一行 |
| 合集里没法挑着听（100 首只能全听或全不听） | 合集面板每行有**启用/禁用**开关，顶部一键「全部启用 / 全部禁用」；禁用的不播、不进队列 |
| 播放条左边「随机」+ 右边「循环」两个按钮，能同时点亮 | **一个按钮**循环切换：列表循环 → 单曲循环 → 随机 → 顺序 |

## 一、逐条对账：哪个现象对应哪行代码

| # | 你反馈的现象 | 根因（代码位置） |
|---|---|---|
| 1 | 合集「详情」界面没有返回 | 搜索结果行的 ⓘ 按钮直接 `currentView = 'parsed'` 再解析（`app.js:1572`），而解析页头部**只画了标题和播放全部**，没有任何返回入口（`app.js:933`）。走进来就出不去了 |
| 2 | 队列跟播放界面不符 | ① 点行播放时传的名字是**旧队列名**：`playTracks(tracks, i, queue.name || '')`（`app.js:1618`）—— 你从搜索点播放，队列里却写"来自「我喜欢」"；② 队列直接**引用**源数组本身（`app.js:338`），不是副本，源列表一动队列跟着动 |
| 3 | 合集里想只听几首 | 目前"合集"在收藏/歌单里就是一个普通曲目对象，**没有"这一行由哪些曲目组成"的记录**，也没有任何按曲目开关的状态 |
| 4 | 顺序播到合集只播第 1 首 | 同一个根：队列里合集只占一行，`cid` 是第 1P 的。播完 `next(1)` 自然跳到下一行（`app.js:324`）。展开面板的 134 集只存在于**面板的内存里**（`collectState`），从没进队列 |
| 5 | 随机 / 循环两个按钮冲突 | 它们是两个**互不相干**的状态：`loopMode`（list/one）和 `shuffled`（true/false）（`app.js:227-228`），点一下各亮各的，可以同时开。`ended` 和 `next()` 分别读它们，语义重叠 |

## 二、改造方案

### P1 详情页返回（最小改动，先修）

- `renderParsed()` 头部左侧加「‹ 返回」按钮，复用 UP 主页已有的返回样式，保持两处一致。
- 点 ⓘ 详情时记下**来路**：`parsedOrigin = { view: currentView, scroll: content().scrollTop }`。
- 返回时还原那个视图（`renderAll()`）并把滚动位置放回去。
- 如果是**粘链接**进来的（没有来路），按钮文案变成「返回搜索」，行为同今天。
- 详情页顺带把当前这行是不是合集写进副标题（`共 N 个分 P / 已识别到合集共 M 集`），否则用户不知道自己在看什么。

### P2 播放队列 = 来源界面的快照

- 新增 `viewLabel()`：把 `currentView` 翻成中文名 —— 搜索页带关键词（`搜索：真栗`）、歌单用歌单名、UP 主页用 `@UP名 的视频`、其余用「我喜欢 / 最近播放 / 发现」。
- 播放入口统一改成 **`playTracks(await buildSequence(列表), 起点, viewLabel())`**：点整行、播放全部、发现、UP 主页、解析页、我喜欢、歌单，全部走同一条路。
- `playTracks` 内部把列表**复制一份**再当队列（`tracks.slice()`），并把来源名存进 `queue.name`。源列表后续增删**不再影响正在播的队列**。
- 队列抽屉副标题：`共 N 首 · 来自「我喜欢」`（已有格式，只是名字终于对了）。
- 抽屉里的「随机打乱」改名「打乱顺序」——它是**一次性打乱队列顺序**，跟"随机播放模式"是两件事，同名会让人以为是开关。

### P3 合集内单曲启用 / 禁用

**存哪儿**（新存档字段，见第三节）：

- `DB.collectOff = { 视频bvid: [被禁用的曲目键, ...] }` —— 存**禁用表**（默认全启用）。
  - 好处：旧存档没有这个字段 = 全部启用，行为跟今天一致，零迁移成本；文件也小。
  - 曲目键 = `bvid#cid`（分P 靠 cid 区分，合集每集自带 bvid，都能唯一定位）。
- `DB.collectParts = { 视频bvid: [ {b, c, page, title, duration, author}, ... ] }` —— 展开过一次就把曲目表**剥掉封面 URL**存下来（约 1–2 KB / 合集），下次打开、下次播放都不用再等网络。

**界面上**：

- 合集面板（右侧抽屉）每一行，在收藏 / 加歌单图标**前面**加一个开关图标：
  - 启用 = 实心对勾；禁用 = 斜杠圆，整行文字变暗（`.off`）。
  - 悬停提示「禁用这一集/启用这一集」。
- 面板顶部按钮区加一个**一键开关**：当前已全部启用 → 显示「全部禁用」；只要有一集被禁用 → 显示「全部启用」。
- 顶部副标题实时显示 `已启用 12 / 134 集`。
- 列表行上的徽章跟着变：全启用时还是「选集 134」，有禁用时显示「选集 12/134」（一眼能看出你筛过）。
- 「播放全部 / 加入队列」只取**启用**的曲目；若整条被禁完，按钮提示「这条合集里的曲目都被禁用了」。

### P4 合集摊平进播放序列（真正的核心）

新增一个函数，所有播放入口都从这里拿序列：

```
async function buildSequence(tracks)      // 返回"真正要按顺序播的一串曲目"
  逐条看 tracks：
    · 普通曲目      → 原样放进去
    · 疑似合集      → 取曲目表（优先本地缓存，没有就查一次 videoInfo 并存下来）
                      → 去掉被禁用的 → 按顺序放进去
                      → 一集都没启用（或被全禁）→ 整条跳过
  任何一条读取失败  → 只对这条退化成"就播它本身"，并提示一次「XX 读取失败，这次只播这一首」
                      （绝不因为一个合集读不到就让整张列表播不了）
```

- 因为队列里已经是"摊平后的曲目"，`next / prev / ended` 的现有逻辑**不用改**就自然衔接：播完合集最后一集，接着播列表下一行。
- 随机模式也是在这条摊平序列上随机 —— 合集里的曲子**平等参与**随机，不再整条跳过一次。
- 列表高亮跟着走：正在播合集的第 5 集时，外面那**一整行**保持"正在播放"高亮（用 `bvid` 认领），不会出现"没有任何一行是亮的"。
- 首次展开需要一次网络请求（主进程有缓存，通常零点几秒；同一合集第二次播放走本地缓存，即时开播）。

### P5 播放模式合并成一个按钮

四种模式，点一次换一个，按钮图标 + 提示同步变，`toast` 报中文名：

| 顺序 | 模式 | 图标 | 行为 |
|---|---|---|---|
| 1 | 列表循环（默认） | ↻ | 播完最后一首回到第一首 |
| 2 | 单曲循环 | ↻¹ | 一首反复播 |
| 3 | 随机播放 | ⤨ | 下一首从队列里随机挑（不会连播同一首）；上一首回到本次随机听过的上一首 |
| 4 | 顺序播放 | → | 播完最后一首**停下**，不再从头开始 |

- 播放条上：**删掉左边那个「随机」按钮**，把合并后的模式按钮放在左边那个位置（原随机位），
  右边空出来的槽位用等宽占位撑住 —— **保证播放键严格居中**（会用离屏截图量出中心点误差来校准，不靠眼估）。
- 关掉"随机"的旧状态，`shuffled` 变量直接删掉，避免两套状态打架。
- 模式记忆进设置（`DB.settings.playMode`），下次打开还是你上次选的那个。
- 队列抽屉里的「打乱顺序」保持独立，和播放模式不冲突。

## 六、已知取舍（说在前面，免得改完你觉得怪）

1. **队列是快照**：播放那一刻定下来，之后你在收藏里加歌/删歌都不会动它。想要"新歌也进队列"，重新点一次播放全部即可。这样才不会播着播着队列自己变。
2. **首次展开合集有一下网络等待**：同一合集只等第一次（之后走本地缓存）。读取失败会退化成"只播这一首"并提示，不会卡死。
3. **顺序模式会停**：这是四种模式里唯一"播完就停"的，其它三种都会继续。
4. **播放模式只有一个按钮**：点一次换一个模式，按钮上会跟着变图标，按钮提示（悬停）写清当前是什么模式。
5. **禁用状态是"跟着合集走"的**：同一个合集在「我喜欢」和某个歌单里都存着时，禁用的是同一套（按视频 bvid 记），不会出现两处不一致。
