| 5 | **（Neo 新报）** 播放条那个按钮点播放后**一直转圈**；不要转圈，**直接显示 `‖`** 就行                                         | 真凶已定位（`app.js:2277`），见 P3 |

**顺带说明**：第 1 条和第 3 条其实是**同一个根** —— 歌词页那层 `backdrop-filter: blur(26px)` 既造成"一坨黑"，又是显卡被打满的一大来源。所以修第 1 条会自动带来第 3 条的一部分收益。

**关于第 4 条的背景调研**（Neo 问过"BetterNCM 的实现和我现在用的哪个更好"）：  
我去读了 `BetterNCM/BGEnhanced` 的源码，结论是 —— **它省显卡不是因为它更聪明，而是因为它压根没做实时模糊**：

- 背景只是一个 `position: fixed; z-index: -1` 的 div（图片 / `<video>`）—— **和我们的背景层一样**
- 面板用的是「**预制全透明**」：`src/index.scss` 里一段注释就这么写的，直接把宿主面板设成 `background: transparent !important`
- **整个 SCSS 里没有任何 `backdrop-filter`，也没有 `filter: blur`**；可读性靠"明度"滑杆压暗背景图
- 它还带一个 C++ DLL（`native/`），用 CEF 的 C API 注入，并开了一个 **30ms 轮询线程**去改 DOM 样式（只为让背景"钉在桌面上"）—— 这部分是**我们不需要也不该学**的

→ 所以正确做法不是"换成它的方案"，而是**把它的成本模型搬过来，同时保留我们的架构**。这正是下面 §2.2 的三档设计。

# 第一部分 · 歌词页 与 播放条小修

## P1 「一坨黑」的真凶

`src/ui/style.css:829-846`：

```css
.lyric-overlay {
  ...
  background: rgba(14, 14, 22, 0.88);   /* ← 88% 不透明，壁纸基本透不过来 */
  backdrop-filter: blur(26px) saturate(140%);
  -webkit-backdrop-filter: blur(26px) saturate(140%);
}
```

**两个问题叠在一起**：

1. **88% 不透明** —— 壁纸几乎完全被盖住，所以看着就是"一坨黑"。那个 `backdrop-filter` 其实**根本没东西可糊**（背后 88% 已经被自己压掉了），纯属白花钱。
2. **`blur(26px)` 覆盖整个内容区**（约 858×558 像素）。而它背后的列表里，「正在播放」那一行的三根柱子是**无限循环动画**（`style.css:444-458` 的 `barPulse`）—— 于是这 26px 的模糊**每帧重跑一次**。
   > Neo 截图里歌词页正好开着，这就是"这次 GPU 直接 90%+"的一大来源。

### 打算怎么改

**核心是"别把整块内容区糊上 + 大幅提高透明度"，三档下都这么做：**

| 模式                                  | `.lyric-overlay` 怎么做                                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **`plain` / `prebake` 档**（默认在这两档之一） | **去掉 `backdrop-filter`**；底色改成"中间几乎全透、上下略深"的纵向渐变（上下 `rgba(8,8,14,.55)` / 中间 `rgba(8,8,14,.26)` 左右，**数值我会出图对比后定**）               |
| **`live` 档（高画质）**                   | **保留 `backdrop-filter`**（Neo 定的：高画质档歌词页也跟着糊），但底色同样**大幅降低不透明度**（从 88% 降到 35% 左右），这样才真的"透出背景 + 毛玻璃"，而不是一坨黑；半径按 L3 从 26px 降到 14px |

**三档共同的部分：**

- `style.css:928-933` 的 `::before/::after` 上下渐隐（现在是 `rgba(14,14,22,0.95)`）跟着降到同一档
- `.lyric-box .l`（`style.css:911-917`）加 `text-shadow: 0 1px 3px rgba(0,0,0,.8)` —— 去掉"糊背景"之后，可读性靠文字自己的投影保证
- 当前句已有的主题色光晕（`style.css:919-924`）保留

> **为什么 `plain` / `prebake` 档要"糊字"而不是"糊背景"**：糊背景是**每帧**的开销（因为背景在动），糊字是**一次性**的开销（文字位置变了才重绘）。网易云 / Spotify 的歌词页都是这么做的。
>
> **为什么 `live` 档也要降不透明度**：现在 88% 不透明时，那个 `backdrop-filter` **根本没东西可糊**（背后已经被自己压掉了）—— 等于花了最贵的钱、什么都没换来。降下来之后 `live` 档才真正"值"这个代价。

## P2 没有歌词时，给个"像样的空状态"

现状有两条路，**两条都是"空"**：

| 情况                       | 现在的行为                            | 代码位置               |
| ------------------------ | -------------------------------- | ------------------ |

| **取词失败**（网络 / 风控 / 接口变更） | **`box.innerHTML = ''` —— 完全空白** | `app.js:2571-2572` |

Neo 看到"空着一片什么也没有"，命中的是**第二条**。

### 打算怎么改

新增一个 `.lyric-empty` 空状态块，**垂直居中**显示：

- **大号歌名**（+ 歌手）
- 一行说明，**区分两种原因**：
  - 纯音乐 → 「这首是纯音乐，没有歌词」
  - 取词失败 → 「这次没取到歌词」+ 一句怎么办（点「词」重试 / 去 ⚙ 设置里填 SESSDATA）
- 一个 **「重新获取」按钮**（复用现有 `btnLyric` 的那套逻辑，不新造轮子）
- 顺带把封面缩略图放上去（可选，做出来看看效果再定）

两条路都走这个空状态：把 `app.js:2571-2572` 的 `innerHTML = ''` 和 `app.js:2593-2595` 的 `（没有歌词）` 统一替换掉。

## P3 播放条那个按钮一直转圈（Neo 新报的）

**现象**：点播放之后，播放条左边那个按钮一直转圈，不变成暂停图标。

**真凶**（`app.js`）：

```js
2275:  audio.addEventListener('play',    () => { $('btnPlay').innerHTML = ic('i-pause'); ... });
2276:  audio.addEventListener('pause',   () => { $('btnPlay').innerHTML = ic('i-play');  ... });
2277:  audio.addEventListener('waiting', () => { $('btnPlay').innerHTML = ic('i-loading', 'spin'); });
 439:  $('btnPlay').innerHTML = ic('i-loading', 'spin');   // 换歌时也先转圈
```

**问题在于**：

- `waiting`（缓冲）时把按钮换成转圈，但**全项目没有任何 `playing` 监听**去把它换回来
- 而 `play` 事件只在"开始播"那一刻触发一次；缓冲结束后触发的是 **`playing`**，没人接
- 所以只要缓冲发生一次（网络音频非常常见），按钮就**永远停在转圈**
- 换歌时（第 439 行）先转圈，如果音频地址取失败或很慢，也一样停在那

**怎么改**（按 Neo 的要求：**不要转圈，直接显示 `‖`**）：

1. 新增一个**唯一的状态刷新函数**，图标完全由"当前到底在不在播"决定：
   ```js
   function updatePlayBtn() {
     const b = $('btnPlay'); if (!b) return;
     b.innerHTML = audio.paused ? ic('i-play') : ic('i-pause');
   }
   ```
2. 在 `play` / `pause` / **`playing`** / `ended` / `emptied` / `error` 上都调它
3. **删掉** `waiting` → 转圈（第 2277 行）
4. **删掉**换歌时的转圈（第 439 行），改成调 `updatePlayBtn()`（此时 `audio.paused` 还是 true → 显示 ▶，点了才变 ‖，符合直觉）
5. 副作用：**丢掉"正在加载"的视觉反馈**。这是 Neo 明确要的（"这个就不用了"）。  
   如果你之后觉得需要反馈，我建议改用**按钮轻微变暗**而不是转圈 —— 不抢眼，也不会"卡住"。

# 第二部分 · 性能：把 GPU 从 90% 打下来

## 2.1 先把"为什么这么高"讲清楚

### 一句话原理

> **`backdrop-filter`（毛玻璃）的含义是"把我背后的画面实时糊一遍"。**  
> **只要合成器还在产帧，它就要每帧重跑一次。**

所以真正的问题不是"糊的是静态图还是视频"，而是 **"合成器为什么一直在产帧"**。

### 8 条根因（按影响从大到小）

| #     | 根因                                                                                               | 位置                                                               | 为什么费显卡                                              |
| ----- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- | --------------------------------------------------- |
| **A** | **4 块常驻面板都挂了 `backdrop-filter: blur(18px)`**                                                     | `.titlebar:229` / `.sidebar:269` / `.topbar:366` / `.player:569` | 播放条那条是 1180×88，每帧重跑 18px 模糊                         |
| **B** | 播放时封面外圈有一条**无限旋转**的弧线，而它**就在播放条内部**                                                              | `.np-cover.spin::before`（`style.css:611-617`）+ 开关在 `app.js:2642` | 播放条有 backdrop-filter → 它内部每帧都在动 → **播放条整条每帧重跑一次模糊** |
| **C** | 「正在播放」那一行的三根柱子**无限跳动**                                                                           | `.idx .bars rect`（`style.css:444-458`）                           | 内容区每帧都在动 → 盖在它上面的歌词页 26px 模糊每帧重跑                    |
| **D** | `.lyric-overlay` 自己挂着 `blur(26px)` 且覆盖整块内容区                                                      | `style.css:840`                                                  | 见 P1（**和"一坨黑"同源**）                                  |
| **E** | 打开设置 / 选集面板时，`.modal` 有 `blur(30px)`、`.collect-panel` 有 `blur(26px)`、`.modal-mask` 有 `blur(6px)` | `style.css:1026/1036/1184`                                       | 打开时叠加在 A 之上，进一步加码                                   |
| **F** | **省显卡措施只对视频背景生效**                                                                                | `app.js:246`                                                     | Neo 用的是**图片背景** → 一点省电措施都没生效                        |
| **G** | 窗口失焦 / 最小化 / 切后台时，B、C 两条无限动画**照跑**                                                               | —                                                                | 看不见的时候还在白烧显卡                                        |
| **H** | `--glass-blur` 默认 18px 偏大                                                                        | `style.css:33`                                                   | 模糊开销 ≈ 面积 × 半径，半径越大越贵                               |

### 一个必须纠正的旧判断

代码里原来写着（`app.js:245-246`）：

> 「背景是图片时不动（**静态图糊一次就缓存住了，毛玻璃几乎不花钱**）」

**这个判断是错的。** 代价不在于"糊静态图"，而在于 **B / C 两条无限动画让合成器永远在产帧，于是所有 `backdrop-filter` 每帧重跑**。  
—— 这正是"用了图片背景（甚至没背景）GPU 还是 90%"的原因。

## 2.2 对策：两个互斥开关 → 三档毛玻璃，默认走省显卡

### 三档效果（由两个开关组合出来）

| 档位                 | 两个开关的状态   | 面板怎么做                              | 成本               | 相当于                          |
| ------------------ | --------- | ---------------------------------- | ---------------- | ---------------------------- |
| **纯半透明**           | 两个都不勾     | 面板只压一层半透明底色，**完全不模糊**              | 最低               | BGEnhanced / BetterNCM 的原样做法 |
| **预先糊好的图**（**默认**） | 只勾「省显卡」   | 面板用**预先用 canvas 糊好的静态壁纸图** + 半透明底色 | ≈ 0（静态图，画一次就缓存住） | —— 我们独有的"又省又好看"              |
| **实时毛玻璃**          | 只勾「实时毛玻璃」 | 面板用真 `backdrop-filter` 实时糊一遍       | **每帧重算，明显更高**    | 现在的 Neko Music               |

> **两个开关互斥**：勾一个会自动取消另一个（这是 Neo 定的形态）。  
> **允许两个都不勾** —— 否则"两个平级开关"就退化成伪装成开关的单选了；  
> 而且"都不勾"正好就是你参考的 BetterNCM 那种做法，是个有意义的最低成本档。  
> **如果你觉得必须始终勾一个，说一声我去掉这一档。**

存进 `settings.glass.mode`：`'plain'` | `'prebake'`（默认）| `'live'`。  
两个开关只是这个字段的两种视图，不存两份状态。

### 设置界面长什么样（草案）

放在「外观」页、「毛玻璃强度」滑杆**上面**：

```
面板毛玻璃
  [ ✓ ]  省显卡 —— 用预先糊好的背景图，观感几乎一样，显卡占用大幅下降
  [   ]  实时毛玻璃（高画质）—— 背后画面实时模糊，更通透，但显卡占用明显更高
  ⚠ 实时毛玻璃在笔记本上更费电、风扇会更响        ← 勾了它才显示这行
  提示：两个都不勾 = 面板完全不做模糊（最省，就是网易云插件那种做法）
```

- **勾「实时毛玻璃」时**：弹一条 toast 提示费显卡；开关**下面常驻一行警示文字**（不是闪一下就没）；**不做二次确认弹窗**
- 「毛玻璃强度」滑杆**保留**：`prebake` 档决定"预先糊的图糊多少"，`live` 档决定实时模糊半径，`plain` 档无作用（可置灰）
- 原来的「降低毛玻璃（省显卡）」开关（`chkPerfLite`）**被这两个开关取代，删掉**
- 「窗口不在前台时暂停」（`chkPauseBlur`）保留，仍只在视频背景下显示

### 「预先糊好的图」档（默认）具体怎么做

**分两种情况，因为视频没法"预先糊"：**

| 背景类型        | `prebake` 档下的行为                          |
| ----------- | ---------------------------------------- |
| **图片背景**    | 生成一张**预先糊好的壁纸图**当面板背景（下面 4 步）            |
| **视频背景**    | 没法预先糊 → **自动降级为「纯半透明」**，并适当抬高底色保证可读      |
| **没有自定义背景** | 一律不挂 `backdrop-filter`（背后是纯色，糊了没有任何视觉收益） |

**图片背景的 4 步：**

1. 设置背景时，用 canvas **一次性**生成一张按「毛玻璃强度」（`--glass-blur`）糊过的壁纸副本
2. 四块面板的 `background-image` 指向它，并加 `background-attachment: fixed`  
   —— 这样每块面板显示的是**壁纸的"对应那一块"**，位置对得上，看起来就是"面板背后的壁纸被糊了"
3. 面板底色照旧 `rgba(var(--glass-rgb), --glass-alpha + --glass-boost)`
4. `backdrop-filter: none`（**必须写 `none`，不能写 `blur(0px)`** —— 后者仍会把背景拷进纹理，省不下来）

> **为什么选 `background-attachment: fixed`**：面板位置都是固定的（`.sidebar` 是 `overflow: hidden`、**不滚动**），所以不会带来滚动重绘；比"给每块面板单独算 offset"简单得多，也少一堆 resize 逻辑。

**重新生成这张图的时机**：换背景图时、拖动「毛玻璃强度」滑杆（防抖 300ms）、窗口宽度变化超过 15% 时。生成一次大约几十毫秒，可接受。

### 「实时毛玻璃」档具体怎么做

保持现状（`backdrop-filter: blur(var(--glass-blur)) saturate(140%)`），代价用 UI 说清楚（见上面的草案）。

### 「纯半透明」档具体怎么做

最简单的一档：面板 `backdrop-filter: none`，底色抬高一点（`--glass-boost`）保证文字可读。  
**这一档就是 BetterNCM 的做法** —— 面板不模糊，背景图靠用户自己调「背景模糊」滑杆去糊。

### 三档**都不变**的部分（跟档位无关，一律生效）

这两条是"纯赚"的，不影响观感，所以不放进开关里让用户选：

1. **窗口失焦 / 最小化 / 切后台** → 一律暂停无限动画（见 S3）—— 看不见的时候省电是无害的
2. **没有自定义背景时**一律不挂 `backdrop-filter` → 两个开关置灰 + 一行说明

> **注意：歌词页不在这里** —— 按 Neo 的决定，歌词页**跟随档位**：`plain` / `prebake` 下不糊、`live` 下跟着糊（见 P1）。  
> 但**三档都大幅降低不透明度**，这是修"一坨黑"的核心。

## 2.3 三档之外、一律生效的优化

### S3 窗口失焦 / 最小化 / 切后台 → 暂停所有无限动画

新增 `body.perf-idle`，对三处无限动画设 `animation-play-state: paused`。  
复用**已有**的失焦 / 最小化探测（`updateBgVideoPlayback()` 里已经在跟踪 `winFocused` 和 `document.hidden`，不用新写一套）。

### S4 统一小修

- `.modal` / `.collect-panel` / `.modal-mask` 的 `backdrop-filter` 也跟随档位：**只有 `live` 档保留**，`prebake` / `plain` 档一律关掉
- 面板底色公式里的 `--glass-boost`：`prebake` / `plain` 档抬高，保证"关掉毛玻璃"后观感不塌
- `--glass-blur` 默认 18px → **12px**（`prebake` 档生成更快、`live` 档也更省；属于顺手）

## 2.4 高画质档（`live`）也要尽量优化

Neo 的追加要求：「**虽然说把高画质分开了，但还是要尽量去优化性能**」。  
下面 3 条**专治 `live` 档**，而且**都不牺牲观感**。

### L1 看不见的内容，一律不许动（最有效的一条）

`backdrop-filter` 之所以贵，是因为"合成器一直在产帧"，而产帧的源头是**动画**。所以：  
**只要某个会动的东西被盖住了、用户看不见，就应该暂停它。**

| 场景             | 谁被盖住了                        | 现在  | 改成            |
| -------------- | ---------------------------- | --- | ------------- |
| 打开整页歌词         | 歌词页背后那一整块列表（含「正在播放」那三根跳动的柱子） | 照样跳 | **暂停**        |
| 打开设置 / 选集 / 弹窗 | 背后整块界面                       | 照样跳 | **暂停**        |
| 窗口失焦 / 最小化     | 全部                           | 照样跳 | **暂停**（S3 已含） |

实现：复用**已有的** `bgOverlayOpen()`（它本来就在判断 4 个遮罩开没开），给 `<body>` 打 `has-overlay`，  
CSS 里对无限动画设 `animation-play-state: paused`。

> **这是纯赚的** —— 用户看不见的东西本来就不该动。  
> 而且它直接砍掉&#x4E86;**"歌词页打开时每帧重跑 26px 模糊"**&#x8FD9;个最大的开销（就是 Neo 截图里 90% 那一下）。

### L2 把「正在播放」的三根柱子从 SVG 动画换成合成动画

那三根柱子现在是 SVG 的 `<rect>` + `transform: scaleY()` 动画。  
**Chromium 里 SVG 的 transform 动画不走合成器，是每帧重新光栅化**（贵）。

改成普通 `<i>` 做柱子 + `transform: scaleY()` 动画 → 走合成器，**每帧只移动图层、不重绘**。  
观感一模一样，成本降一个量级。

### L3 降低模糊半径

`backdrop-filter` 的开销 ≈ **面积 × 半径**，所以半径是个线性杠杆：

- 面板默认 `--glass-blur`：**18px → 12px**
- 歌词页：**26px → 14px**（它是整块内容区，最该降）

观感差别很小（面板背后本来就是壁纸），但开销按比例下来。

> **曾经考虑过、但按你的决定砍掉的一条**：给封面旋转弧线加 `will-change: transform`，  
> 把它提升成独立合成层（理论上让它不再拖累播放条毛玻璃）。  
> **你说不用，所以不做。** 副作用如实说明：`live` 档 + 正在播放时，那条旋转弧线**有可能**仍让  
> 播放条的毛玻璃每帧重算（不同 Chromium 版本行为不一样）。  
> 但这不是新引入的问题（现版本就是这样），而且只出现在 `live` 档；真机上若发现 `live` 占用仍偏高，我们再回来处理。


### 一个必须如实告诉你的事实

**在"静态图片背景"下，`live` 档和 `prebake` 档的画面几乎完全一样。**

原因：`backdrop-filter` 做的就是"把背后那块糊一遍"。而面板背后是**一张不动的壁纸**，  
所以"实时糊"和"预先糊"算出来的**就是同一张图**。

**真正的差别只在一种情况下出现**：有内容从面板背后**经过**（滚动 / 滑动）时，  
实时模糊才是"活的"，预先糊的图是"定格"的。

而现在的布局里，四块面板是 grid 的独立格子、**没有内容会从它们背后经过** ——  
所以老实说，`live` 档在目前这个界面上，**更多是"心理上的高画质"，肉眼差别很小**。

> 这不影响我们把它做出来（你要保留这个选择权），但我不希望你切过去之后觉得"怎么没变"。  
> 如果以后把面板改成浮在内容之上（比如加"内容从面板下滑过"的效果），`live` 档才会真正显出价值。

## 2.5 预期效果（诚实说明）

- **能保证**：上面 A~H 里"每帧重算"的那条路径，在 `prebake` / `plain` 两档下被**彻底拿掉**（有断言可验，见第四部分）
- **不能保证**：降到网易云的 22%。网易云是 CEF 应用、本身就没开 `backdrop-filter`，起点就不同
- **测不了**：真实 GPU 百分比。沙箱是**纯软件渲染**，测出来的数没有意义 → **最终要 Neo 真机看任务管理器**

# 第五部分 · 已知取舍（先说清楚，不藏）

1. **`prebake` 的"预先糊好的图"和 `live` 的真毛玻璃有细微差别**：真毛玻璃糊的是"面板背后那一块"，预先糊的图糊的是整张壁纸。因为壁纸是 `cover` 铺满、面板位置固定，**两者糊到的内容其实一致**，但边缘采样方式略有不同，肉眼几乎看不出。
2. **`prebake` / `plain` 档下面板后面的内容不再被实时模糊**。四块面板都在边缘、背后只有壁纸，所以看不出来；但如果以后有内容滚到面板下方，就会露出差别。
3. **`prebake` + 视频背景的观感会比 `live` 略差**：视频没法预先糊，`prebake` 档下只能"半透明不模糊"。这是物理限制，不是实现偷懒。
4. **依然测不了真实 GPU 百分比** —— 沙箱纯软件渲染。最终结论以 Neo 真机的任务管理器为准。
5. **不承诺降到 22%**。网易云起点就不同（它没用 `backdrop-filter`）。我能做的是把"每帧重算"这条路径在 `plain` / `prebake` 档下彻底拿掉。
6. **预先糊的图会让壁纸在内存里多存一份**（按窗口尺寸生成，1080p 约 1~3 MB 的 JPEG data URL），可以接受。
7. **`coverSpin`（封面旋转）保留** —— 它是"正在播放"的视觉信号；在 `plain` / `prebake` 档下面板本就没有 `backdrop-filter`，所以它不会再触发重模糊。**`live` 档下它仍有可能让播放条毛玻璃每帧重算**（见 §2.4 末的说明）—— 按你的决定，本轮**不加 `will-change`**，暂不处理。
8. **优雅降级**：如果 `ctx.filter = 'blur()'` 在你机器上不支持（Chromium 是支持的，但万一），`prebake` 档会自动退回「**纯半透明底色、不模糊**」—— 也就是 BetterNCM 的做法。**不会白屏，也不会偷偷退回实时毛玻璃**。
9. **`background-attachment: fixed` 现在安全**，因为四块面板都是固定位置、`.sidebar` 还是 `overflow: hidden`。**如果以后把面板改成会滚动的，这条要重新评估。**
10. **切换模式时会有一次几十毫秒的重绘**（生成 / 丢弃那张预先糊的图）。可接受，不会卡到能感觉出来。
