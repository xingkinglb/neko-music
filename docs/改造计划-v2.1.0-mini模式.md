**一句话结论**：**mini 模式不新建窗口** —— 就用现在这个窗口，把它缩小 + 换一套 CSS。

**为什么这条很重要**（不是偷懒，是避坑）：你项目里已经有"第二个窗口"的先例（桌面歌词，`src/main.js:598`），它的代价是要靠 **6 个 IPC 通道**来回推歌词、进度、样式（`lyric:push` / `lyric:style` / `lyric:resize` …）。mini 模式如果也新开窗口，播放状态、音量、歌词、背景**全都要在两个窗口之间同步** —— 那是这类功能最容易出 bug 的地方。用同一个窗口就**什么都不用同步**。

## 一、参考资料（别人是怎么做的）

### 1.1 mini 模式

主流音乐软件（网易云、QQ 音乐、酷狗）的做法**完全一致**：**不新开窗口**，而是把主窗口缩小 + 换一套界面布局，再留一个按钮回到完整模式。

- 好处：播放状态、进度、音量、歌词、背景**全都原地不动**。
- 你截图里那两个"▢ / 还原"图标（图2、图3 的右上角）就是"回到完整模式"的出口 —— 说明它们也是同一个窗口换布局。

### 1.2 参考项目对照：`wood3n/biu`（同类 Electron 播放器）

Neo 给了一个同类开源项目 [wood3n/biu](https://github.com/wood3n/biu)（Electron + React + TypeScript，2725 star，也是个 B 站音乐播放器）。
我把它的 mini 实现读了（`electron/mini-player.ts` + `electron/ipc/window.ts` + `src/common/utils/mini-player.ts`），完整笔记见 `docs/参考实现研究-biu.md`。**它和我们想的不一样**：

| | biu 怎么做 | 我们怎么做 |
|---|---|---|
| 窗口 | **另开一个小窗** `new BrowserWindow({ width: 320, height: 100, skipTaskbar: true })`，同时把主窗口 `hide()` | **同一个窗口缩小**（`setBounds` + `body.mini`） |
| 尺寸 | 固定 320×100，横条，**没有播放列表** | 收起 420×132 / 展开 420×520（图3 有列表） |
| 模式标记 | URL hash（`loadFile(indexPath, { hash: 'mini-player' })`） | `body.mini` 类 |
| 状态同步 | 主窗口推给 mini 窗口（`BroadcastChannel` 协议，约 150 行） | **不需要**（同一个窗口，DOM 原地复用） |

**为什么不照抄它的"独立小窗"（两条硬伤）：**

1. **`skipTaskbar: true` 会让任务栏图标消失** —— 而 v2.2.0 的「悬停任务栏图标出缩略图按钮」（图4）**正是挂在任务栏图标上的**。
   进了 mini 反而没有任务栏图标可悬停，两条需求**直接打架**。我们用同一个窗口缩小，任务栏图标**一直在**。
2. **两个窗口就要同步状态** —— 它为此写了一整套协议（`src/common/utils/mini-player.ts`，约 150 行：
   `BroadcastChannel` + `init/seek/next/prev/togglePlay/togglePlayMode` 命令 + 状态快照 + 订阅/退订），
   因为 mini 窗口**自己不播歌**，播放状态、进度、歌名、封面全靠主窗口推。
   Neko 是 vanilla JS（没有 React / zustand），照搬这套只会**更麻烦**；用同一个窗口则**一行同步代码都不用写**。

> ✅ **它唯一值得学的是"思路"**：它用 URL hash 标记"这个窗口现在是 mini"，我们用 **`body.mini` 类**做等价的事 ——
> 都是"**同一个页面 + 一个模式标记**"，只是标记载体不同。这反过来印证了我们 §3.1 的设计方向是对的。
>
> 📌 另外它 mini 窗是 `alwaysOnTop: true` 的**置顶**小窗 —— 这个我们**不做**（Neko 的 mini 仍然是普通窗口，不抢焦点、不压别的程序）。

## 三、方案：mini 模式

### 3.1 总体思路

三步：

1. **记住**进 mini 之前的窗口位置和大小（`win.getBounds()`）。
2. 加 `body.mini` 类 → CSS 换布局；同时把窗口缩小（`setBounds`）并限制尺寸（`setMinimumSize` / `setMaximumSize` / `setResizable(false)`，免得用户拖乱了布局）。
3. 退出 mini 时去掉 `body.mini`，窗口**还原到记住的位置和大小**。

> 这个"**同一个窗口 + 一个模式标记**"的思路，参考项目 biu 用的也是同一招（它用 URL hash，我们用 `body.mini` 类，等价）——
> 见 §1.2。区别只是**它把标记挂在一个新开的窗口上**，我们挂在同一个窗口上。

### 3.2 mini 收起态（对应图2）

窗口尺寸建议 **420 × 132**。

```
┌────────────────────────────────────────────────┐
│ ┌──────┐    ⏮  ⏸  ⏭      ♡  🔊  ☰      ✕ ▢  │   ← 整条可拖动
│ │ 封面 │                                       │
│ └──────┘                                       │
│  誰よりも - KG/菅原纱由理（THE SxPLAY）        │   ← 歌名（超长省略号）
└────────────────────────────────────────────────┘
```

**全部复用现成元素，不新造控件**：

| 图2 里的东西 | 用项目里哪个 |
|---|---|
| 封面 | `#npCover`（`index.html:294`） |
| ⏮ ⏸ ⏭ | `#btnPrev` / `#btnPlay` / `#btnNext`（`index.html:311-313`） |
| ♡ | `#btnFav`（`index.html:299`） |
| 🔊 | `#btnMute` + 音量滑杆（`index.html:350`） |
| ☰ | `#btnQueue`（`index.html:341`） |
| 歌名 | `#npTitle` + `#npSub`（`index.html:296-297`） |
| ✕ | `#winClose`（`index.html:229`） |
| ▢（回完整模式） | 新增 `#btnRestoreFull`（比复用 `#winMax` 语义更清楚） |

**CSS 怎么改**（`style.css` 新增一节）：

```css
body.mini .app {
  grid-template-columns: 1fr;
  grid-template-rows: 1fr;              /* 只留一块 */
  grid-template-areas: "player";
}
body.mini .sidebar,
body.mini .topbar,
body.mini .content,
body.mini .titlebar { display: none; }  /* 其余全藏 */
body.mini .player { /* 重排成图2 那一条：封面左、控制中、杂项右、歌名下 */ }
```

> ⚠️ **一条必须守住的铁律**：`body.mini` 下**不能**给 `.app` 加 `transform` / `filter` / `opacity`。
> `style.css:278-280` 已经写着原因 —— 它们会生成 "backdrop root"，把子元素的毛玻璃打成一块纯色。

### 3.3 mini 展开态（对应图3）

在 mini 条下面挂一块**列表**，窗口高度从 132 → 约 **520**。

- **列表内容：当前播放队列**（复用已有的队列数据和渲染）。理由：图3 那条列表是"接下来要播什么"，队列最贴。
  - 若你更想看"当前正在浏览的那个列表"（比如刚搜出来的结果），说一声，我换数据源（§8 Q2）。
- 图3 底部那条"⏸ 誰よりも （比任何人都）" = 正在播放那一行，加个高亮即可。
- **触发**：图2 里那个 ☰（`#btnQueue`）在 mini 模式下**不再开右侧抽屉**，改成"就地展开 / 收起这块列表"。

### 3.4 进 / 出 mini 模式

| 入口 | 说明 |
|---|---|
| 标题栏新按钮（图1 红框那个） | 位置在**最小化左边**，顺序变成 `[mini] [min] [max] [close]` |

### 3.5 存档

记住"上次是不是 mini"和"完整模式下的窗口尺寸"，下次打开还原：


### 6.2 无边框窗口的三个加固（从 biu 学到的）

参考项目 biu 在**自绘标题栏**的窗口上做了三处拦截，我看了觉得是真实痛点，**本轮顺手一起加**（`src/main.js` 里 `createWindow()` 内，约 `main.js:225` 之后）：

```js
// ① 拦掉 Windows 系统菜单（WM_INITMENU = 0x0116）。
//    无边框窗口按 Alt+Space、或在标题栏右键，会冒出系统那个"还原/移动/大小/最小化/关闭"菜单，
//    和我们自绘的界面格格不入。biu 的做法是"拦下这一条消息，把窗口瞬间禁用再启用"。
if (process.platform === 'win32') {
  mainWindow.hookWindowMessage(0x0116, () => {
    mainWindow.setEnabled(false);
    setTimeout(() => mainWindow.setEnabled(true), 100);
    return true;
  });
}

// ② 禁掉 Ctrl+R / Cmd+R 刷新页面。
//    误按会把整个界面重载 —— 歌还在放，但界面回到首页，看着像崩了。
mainWindow.webContents.on('before-input-event', (event, input) => {
  if ((input.control || input.meta) && input.key.toLowerCase() === 'r') event.preventDefault();
});

// ③ 禁掉 Chromium 默认右键菜单（网页里右键会冒出"返回/重新加载/检查"那一坨）。
mainWindow.webContents.on('context-menu', (e) => e.preventDefault());
```

| 加固项 | 为什么值得做 |
|---|---|
| 拦 `WM_INITMENU` | 无边框窗口 + 自绘标题栏下，系统菜单会**穿透出来**，很出戏 |
| 拦 `Ctrl+R` | 界面重载 = 看着像崩溃（音乐却还在响），用户会以为出 bug |
| 拦右键菜单 | 冒出 Chromium 原生菜单，和自绘风格完全不搭 |

> ⚠️ **① 有个副作用要注意**：`hookWindowMessage` 是 Electron 的实验性 API（`win.hookWindowMessage`），
> 只对 Windows 有效；macOS/Linux 上这段要用 `process.platform === 'win32'` 跳过（上面已经这么写了）。
> 它拦的是"系统菜单弹出"这一个消息，**不影响**我们自己画的任何菜单（比如 §3.3 的展开列表）。

## 七、已知取舍（先说清楚，不藏）

1. **mini 模式下"背景模糊 / 面板不透明度"这些设置照旧生效**，但 mini 窗很小，背景基本被封面和控件盖住。
   如果你希望 mini 模式**强制用纯色底**（更清爽、也省一点显卡），说一声我加一条（§8 Q4）。
2. **mini 模式不做"拖边缘自由缩放"**（`resizable: false`）—— 布局是围绕两个固定尺寸（收起 420×132 / 展开 420×520）设计的，允许自由拖会拖出难看的中间态。你要是想能拖，我改成"只在两个尺寸之间吸附"。
3. **mini 模式下窗口仍占任务栏一个位置**（这是对的 —— v2.2.0 的任务栏缩略图按钮和托盘菜单都作用在它身上）。
4. **这是"多了一个按钮"，不是"改了已有行为"** —— 不进 mini 的话，一切和 v2.0.2 完全一样。老存档零迁移。
