## 一、逐条真凶（行号级 + 实测）

### 1.1 为什么视频背景"没铺满整个界面"

**先看实测**（探针 `.tmp/probe-ui.js`，量的是真实计算样式，不是我的推断）：

```
===== A) 视频背景 + prebake（默认档） =====
body.classes = glass-prebake has-bg          ← 注意：没有 has-imgbg
--bg-dim=0.55  --glass-alpha=0.55  --glass-img=none
  titlebar : --panel-a=calc(0.55 + 0.04 - 0.05)   bg=rgba(16, 16, 26, 0.54)
  sidebar  : --panel-a=calc(0.55 + 0.04 + 0.16)   bg=rgba(16, 16, 26, 0.75)
  topbar   : --panel-a=calc(0.55 + 0.04 - 0.12)   bg=rgba(16, 16, 26, 0.47)
  player   : --panel-a=calc(0.55 + 0.04 + 0.1)    bg=rgba(16, 16, 26, 0.69)
  content  : --panel-a=(未定义)                    bg=rgba(0, 0, 0, 0)   ← 完全透明
```

**结论（实测）**：视频背景时，四块面板压着 **47% ~ 75%** 的深色（`rgb(16,16,26)`），而内容区是 **0%**。
所以视频在内容区看得清清楚楚，一进面板就被盖掉大半 —— 你看到的"背景没覆盖全部界面"就是这个。

**为什么视频会走到这条最暗的路**（行号级）：

- `style.css:250-261` —— 面板换成"预先糊好的壁纸图"这套，**前提是 `<body>` 带 `has-imgbg`**。
- `app.js:287` —— `has-imgbg` 只在 **`s.bg.kind !== 'video'`** 时才可能打上（注释原文：视频没法预先糊）。
- 于是视频背景时 `has-imgbg` **不打**（实测 A 里 `body.classes` 确实没有它），面板退回基础规则：
  - `.titlebar` `style.css:296` → `--panel-a: calc(0.55 + 0.04 - 0.05)`
  - `.sidebar` `style.css:342` → `+0.16`（注释写着"侧边栏字最多，故意比别处实一点"）
  - `.topbar` `style.css:440` → `-0.12`
  - `.player` `style.css:671` → `+0.10`
- 每块面板各写一个偏移量 → 不但都偏暗，**四块还互不相同**。这就顺手引出了第 2 条。

### 1.2 为什么"各框架透明度不一样"

**实测**（同上，A 组）：`0.47 / 0.54 / 0.69 / 0.75` —— **四块面板四个值**，最大差 **28 个百分点**。

来源就是 `style.css` 里四处分头写的偏移量（`-0.05 / +0.16 / -0.12 / +0.10`，行号见 1.1）。

再看**图片背景**那组实测：

```
===== B) 图片背景 + prebake（默认档） =====
body.classes = glass-prebake has-bg has-imgbg
  titlebar/sidebar/topbar/player 四块:
    bgi = linear-gradient(rgba(16,16,26,0.26), …), linear-gradient(rgba(0,0,0,0.55), …), url("data:image/jpeg…")
  content: bg=rgba(0,0,0,0)
```

**结论（实测）**：图片背景时四块面板**彼此是一样的**（都走 `style.css:250-261` 那条规则，不用各自的 `--panel-a`），
但它们比内容区**多压了一层 `rgba(16,16,26,0.26)`** —— 所以"面板比内容区暗一档"，跟内容区不是一家人。

→ 综合起来：**视频档四块互相不一样、且都太暗；图片档四块一样、但整体比内容区暗。** 你两种背景都试过，感觉自然就"怪怪的"。

### 1.3 为什么歌词页背后还显示上一个界面

**实测**（探针 C 组，歌词页打开后）：

```json
{ "overlayShow": true,
  "bodyClasses": "glass-prebake has-bg has-imgbg lyric-open",
  "contentVisibility": "visible",      ← 内容区还看得见
  "overlayBg": "rgba(8, 8, 14, 0.34)" } ← 歌词浮层只有 34% 不透明
```

**根因**：`style.css:936` 把整页歌词的底色降到 `rgba(8,8,14,0.34)`（v2.0.0 为了"透出壁纸"做的），
而它**盖住的正是 `.content`（发现页 / 最近播放的列表）**。34% 的遮挡挡不住列表 —— 于是列表透出来，看着脏。

> 说明一下这不是"没做"，而是 v2.0.0 的方向偏了：当时想的是"透出壁纸"，但没把"透出列表"排除掉。
> 正确做法是：**透出壁纸，但把列表藏起来。**

## 二、打算怎么改

### 2.1 核心：把"面板压暗"收敛成**一个**变量

现在面板的暗度来自 5 个地方（`--glass-alpha` + `--glass-boost` + 四处偏移 + 写死的 `0.26`）。
改成 **1 个**：

```css
/* style.css :root 里新增（默认 0.12 = 面板比内容区只多压一点点） */
--frame-a: 0.12;
```

四块面板统一（`style.css:284-305 / 338-350 / 435-443 / 667-680`）：

```css
.titlebar, .sidebar, .topbar, .player {
  --panel-a: var(--frame-a);              /* ← 四处偏移量全部删掉 */
  background: rgb(var(--glass-rgb) / var(--panel-a));
  backdrop-filter: blur(var(--glass-blur)) saturate(140%);
}
```

prebake（图片背景）那条（`style.css:250-261`）：把写死的 **`0.26` 换成同一个 `--frame-a`**：

```css
body.glass-prebake.has-imgbg .titlebar, … .player {
  background:
    linear-gradient(rgb(var(--glass-rgb) / var(--frame-a)), …) center/cover no-repeat fixed,   /* 0.26 → var(--frame-a) */
    linear-gradient(rgb(0 0 0 / var(--bg-dim)), rgb(0 0 0 / var(--bg-dim))) center/cover no-repeat fixed,   /* 不动：与内容区同源 */
    var(--glass-img) center/cover no-repeat fixed;
}
```

**这样一改，三种情况全对齐**：

| 情况 | 面板最终长什么样 | 和内容区比 |
|---|---|---|
| 视频背景 | `rgb(16 16 26 / 0.12)` 压在（已被 `--bg-dim` 压暗的）视频上 | 只多 12% → **视频铺满整个窗口** ✅ |
| 图片背景 | 预先糊好的壁纸 + 与内容区**同一条**压暗罩 + 12% 底色 | 亮度几乎一致，只是面板那份是"糊的" ✅ |
| 无背景 | 深色底 + 12% 底色 | 无影响 |

**四块面板从此完全一致**（同一个 `--frame-a`，没有偏移量）。

### 2.2 设置项：这正是你说的"两个设置"

其实**已经是两根滑杆**，只是原来那根语义乱了。改完是这样：

| 设置 | 作用范围 | 默认 | 说明 |
|---|---|---|---|
| **背景压暗**（已有，`rngDim`） | **整块背景**（含内容区 + 面板背后） | 55% | 不动 |
| **面板不透明度**（原「玻璃透明度」重做，`rngGlassAlpha`） | **四块框架**比内容区**多**压多少 | **12%** | 拖到 0 = 面板与内容区完全一致（纯壁纸） |

具体：
- `index.html:568-572` —— 标签「玻璃透明度 55%」→「面板不透明度 12%」；滑杆 `min=10 max=95 value=55` → **`min=0 max=40 value=12`**；提示语改成"拖到 0 = 面板和内容区一样透"。
- 存档：新增 `settings.glass.frameAlpha`（缺省 **0.12**）；旧的 `glass.alpha` **退役**（读到忽略）。
  - ⚠️ **这一条我故意打破了"缺省 = 旧行为"的老规矩**：旧行为（面板 47%~75% 深色）**正是你要修的东西**，所以老存档也一律走新默认 0.12。
    如果你希望"老存档保留旧观感、只有你手动调才变"，说一声我改成条件迁移。
- `app.js:2154` `bindRange('rngGlassAlpha', …)` → 写 `DB.settings.glass.frameAlpha`；`app.js:340-357` `applyAppearance()` 里把 `--frame-a` 写到 `<html>` 上（和 `--bg-dim` 一样）。
- `--glass-boost` 整个退役（`:root` 声明、`style.css:237-238` 那条、以及四处 `--panel-a` 计算里对它的引用）。

### 2.3 歌词页：透出壁纸，但藏掉列表

`style.css` 新增一条（放在 `.lyric-overlay` 那一节里）：

```css
/* 打开整页歌词时把内容区藏起来：背后只剩壁纸，不再透出上一个页面。
   ★ .lyric-overlay 挂在 <body> 下（不在 .app 里），所以藏 #content 不会连它一起藏掉。 */
body.lyric-open #content { visibility: hidden; }
```

- `body.lyric-open` 由 `app.js:437-442` 的 `syncPauseClasses()` 维护，`toggleLyrics()`（`app.js:3003`）里已经会调它 → **不用改 JS**。
- 顶部的搜索栏（`.topbar`）**照旧露着**（歌词浮层从它下沿才开始铺，`style.css:927`），所以"点一下还能收起歌词"这条不受影响。
- 遮罩底色 `rgba(8,8,14,0.34)`（`style.css:936`）**先不动**；如果你觉得背后壁纸还偏暗，我再单独调。

## 五、已知取舍（先说清楚，不藏）

1. **面板"糊"的效果只在图片背景 + `prebake` 档下才有**。视频背景时面板只能"淡淡压一层"（因为视频没法预先糊，实时糊又是我们 v2.0.0 特意拿掉的每帧开销）。
   → 想要"视频也被糊住"的磨砂感，只有切「实时毛玻璃」档，代价是显卡占用变高。
2. **面板变透后，文字对比度会下降**（尤其视频背景 + 深色主题）。默认给 12% 是折中；嫌不够清楚就往右拉滑杆。
   如果你觉得默认就该更实一点，告诉我一个数值我改默认。
3. **这是"默认观感"的改变**：老存档也会跟着变（见 §2.2 的说明）。你要是想保留旧观感，说一声。
4. **歌词页遮罩的 0.34 本轮不动** —— 先把"列表透出来"这个脏源去掉，亮度够不够你看了再说。
5. **测不了真实 GPU 百分比**（沙箱纯软件渲染）—— 本轮不涉及性能路径的增删，`prebake` 档仍是 `backdrop-filter: none`，所以显卡占用**不该变差**（有静态断言守）。
