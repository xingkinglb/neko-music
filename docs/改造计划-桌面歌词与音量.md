# 改造计划：桌面歌词 + 音量交互 + 歌词入口重排

> 目标：把「歌词」从一个整页弹层，升级成**像主流音乐软件那样的桌面悬浮歌词**；
> 顺手把音量控件和整页歌词的入口重排到更符合直觉的位置。
> 这份文档是**动手前的施工图**，看完确认后再改代码。

## 〇、先说结论：这一版会变成什么样

| 你现在看到 | 改完以后 |
|---|---|
| 播放条右侧一根横着躺的音量条 | 只剩一个音量图标；鼠标移上去，**上方浮出一根竖向调节条**（YT Music 那种） |

## 一、音量控件：悬停展开的竖向滑杆

参考 image#1（YouTube Music）：一个圆角深色胶囊，里面是竖向轨道 + 圆形滑块。

**默认状态**：播放条最右侧只有一个 18px 的音量图标，**不占额外宽度**（省下的地方给歌词按钮）。

**交互清单**（都是主流软件已经养成的习惯，照着做不用用户学）：

| 操作 | 结果 | 参照 |
|---|---|---|
| 鼠标移到图标上 | 上方浮出竖向滑杆，**向上弹出**、带淡入 | YouTube Music |
| 移到滑杆本身 | 保持展开（悬停区是整个容器，不是只有图标） | 所有家 |
| 移开 | 400ms 后自动收起（给一点缓冲，避免手抖） | YouTube Music |
| 拖动滑块 | 实时改音量，停手后写入存档（沿用现在的逻辑） | — |
| **单击图标** | **静音 / 取消静音**，图标变斜杠样式 | 网易云 / Spotify |
| **在图标或滑杆上滚轮** | 音量 ±5 | 主流共识 |
| 悬停时 | 图标旁边显示当前音量数字（如 `72`） | YouTube Music |
| `↑` `↓` | 音量 ±5（已有快捷键，保留） | — |

**视觉**：胶囊底为半透明深色 + 细边框（跟随主题的 `color-mix`）；轨道用主题色实心填充；滑块是圆形 + 一圈主题色描边 + 深色内芯 —— 和 image#1 一致。

**为什么竖向**：横条会跟进度条抢视觉重心，而且播放条右侧本来就挤。竖条默认不显示，等于把空间还给了按钮。

## 二、桌面悬浮歌词（这次的真正主体）

参考 image#2：歌词直接浮在其他软件（浏览器、文档）上面。

### 2.1 它是什么

一个**独立的置顶小窗口**（不是盖在播放器里的浮层），无边框、无任务栏图标、背景透明、**总在最前**。
主窗口还在播放，它为播放服务 —— 你可以把播放器最小化，歌词照样挂在屏幕上。

### 2.2 长什么样

- **双行**：当前句（亮、主题色描边/发光）+ 下一句（暗）—— 默认「当前句 + 下一句」；
  > 说明：你的 image#2 里两行是**原文 + 翻译**（日文一行、中文一行）。这个我们暂时做不到：
  > B 站的字幕接口一次只给**一条轨道**，而我们优先取中文轨道，拿不到"日文 + 中文"两份。
  > 所以默认按「当前句 + 下一句」显示。等以后需要，再加一个"第二行显示翻译（该视频有翻译轨道时）"的选项 —— 先留个口子，这一版不做。
- 半透明深色圆角底（默认不透明度 85%）+ 文字阴影/细描边，保证在**任何壁纸、任何网页**上都看得清；
- 字号默认 22px，可 12–48px 调；
- 当前句左侧有个 3px 的小竖条（主题色），一眼能看出"现在唱到这句"。

### 2.3 交互（对着网易云/QQ音乐的成熟做法）

| 操作 | 结果 |
|---|---|
| 按住歌词拖动 | 移到屏幕任意位置；**位置自动记住**，重启后还在原处 |
| **单击歌词** | 浮出工具条（**不是悬停** —— 悬停太容易误触，鼠标一扫就弹出来很烦） |
| 再单击一次 | 收起工具条 |
| **鼠标移开歌词 3 秒** | 工具条自动淡出收起 |
| 拖动超过 4px | 算拖动、不算单击（手抖不会误弹出工具条） |
| 点「锁定」 | 锁住位置（不会误拖动），按钮仍可点；再点一次解锁 |
| 点「A- / A+」 | 字号 12–48px 步进，实时生效并存档 |
| 点「关闭」 | 关掉悬浮窗（等于再点一次「词」按钮） |
| 鼠标穿透（设置里开） | 点歌词会"穿"到下面的软件上，适合边玩边看词 |

**工具条用图标，不用文字**（和播放条上其他按钮保持一致，7 个图标一字排开）：

| 图标 | 作用 | 鼠标移上去的提示 |
|---|---|---|
| 左双三角 + 竖条 | 上一首 | 上一首（`Ctrl+←`） |
| 三角 / 双竖条 | 播放 / 暂停 | 播放（`空格`） |
| 竖条 + 右双三角 | 下一首 | 下一首（`Ctrl+→`） |
| 小号字母 A | 字号变小 | 字号 −2 |
| 大号字母 A | 字号变大 | 字号 +2 |
| 锁（开 / 合） | 锁定位置 | 锁定后不会误拖动 |
| 叉 | 关闭悬浮窗 | 关闭（`Ctrl+L`） |

每个图标都带上面这栏**悬停提示**，移到上面就知道它是干什么的，不会认不出。

> 两处跟着调整：
> ① 原计划的「双击歌词 = 播放/暂停」**去掉** —— 双击是两次单击，会和"单击弹工具条"打架；播放控制就走工具条里的按钮。
> ② 鼠标穿透开启时，单击**不会**弹工具条（点击已经穿到下面的软件去了），想关穿透只能回主窗口设置 —— 理由见下面那条。

> 注意：**穿透开关为什么必须放在主窗口的设置里**：开启穿透后，鼠标点不到悬浮窗自己，也就没法用它的按钮把穿透关掉。这是主流软件都踩过的坑 —— 关闭入口只能放在主窗口。我会在设置里注明这一点。

### 2.4 「词」按钮的新语义

- **点一次 = 开**：立刻把当前这首歌的歌词推给悬浮窗并显示；按钮高亮（主题色）。
- **再点一次 = 关**：悬浮窗消失，按钮恢复。
- **不随换歌消失**：换歌后自动换成新歌的歌词（前提是拿得到）；这就是你说的"一直存在，直到下次点击"。
- 快捷键 `Ctrl + L` 同样改为切换桌面歌词。
- 拿不到字幕时，仍然是按钮上方飘一句提示然后消散（沿用现在的做法）。

## 三、和「自动加载歌词」的联动（你提的这条，我这样落地）

现在这两个功能是散的，逻辑上必须绑在一起才不别扭：

```
   桌面歌词 = 开
        │
        ├─→ 自动把「自动加载歌词」也置为开（否则换歌后悬浮窗没词可显示）
        │   并 toast 提示：已同时开启「自动加载歌词」
        │
   设置里手动关闭「自动加载歌词」
        │
        └─→ 认为你不需要歌词了 → 同时关闭桌面歌词，并 toast 提示
```

一句话规则：**「自动加载歌词」是供词能力，「桌面歌词」是用词方式。要显示，就必须能取。**

**设置面板同步改造**：现在「外观」页里塞了个歌词开关，位置很别扭。新增独立的 **「歌词」标签页**（主流软件都是这么分类的），收纳：

- `自动加载歌词` 开关（保留，默认关）
- `桌面歌词` 开关（和播放条「词」按钮联动，两边同步）
- `显示行数`：单行 / 双行（默认双行）
- `字号` 滑杆 12–48（默认 22）
- `不透明度` 滑杆 30%–100%（默认 85%）
- `锁定位置` 开关、`鼠标穿透` 开关（附上面那句说明）
- `恢复默认位置` 按钮（万一拖到屏幕外面找不回来）

## 四、整页歌词：挪到封面入口 + 顺手优化

### 4.1 入口改成点封面

播放条最左边那张封面（image#3 红框处）变成可点：

- **悬停**：封面轻微放大、浮出一层半透明遮罩 + 一个「词」小图标，鼠标提示为「查看歌词」；
- **点击**：打开**现有的整页歌词**（保留你现在满意的那个布局），`Esc` 或右上角的关闭按钮收起；
- **播放中**：封面外面套一圈缓慢旋转的唱片渐变（主流做法，一眼看出正在播放）；
- 这张封面在没歌的时候不可点。

### 4.2 整页歌词顺手补三件主流能力

1. **点某一句歌词 → 跳到那一句的时间**（几乎每家都有，找副歌特别好用）；
2. 顶部显示**歌曲名 + 歌手**；字号比正文大一点，当前句依然居中滚动（沿用已修好的滚动逻辑）；
3. 页面右上角加一个 **「桌面歌词」开关** —— 不用退回主界面就能开悬浮窗。

### 4.3 新的快捷键表

| 按键 | 作用 | 变化 |
|---|---|---|
| `Ctrl + L` | 开/关**桌面歌词** | 语义从"整页歌词"改成"桌面歌词" |
| `Ctrl + D` | 开/关**整页歌词** | 新增（原来没有独立入口） |
| `Esc` | 收起整页歌词 / 关闭设置 | 不变 |
| 其余（空格、←→、↑↓、Ctrl+←→、F11） | 不变 | 不变 |

> 悬浮窗被点中时，空格 / ←→ 也能控制播放，但**不做全局快捷键** —— 全局抢占空格会让你在别的软件里打不了字。

### 5.2 四个关键风险，先处理掉

1. **透明窗口 + 磨砂玻璃在 Windows 上不可靠**
   → 悬浮窗**不用** `backdrop-filter`，改用"半透明纯色 + 文字阴影与细描边"，这是主流软件的实际做法，稳定且更清晰。

2. **置顶会不会被全屏软件盖住**
   → 用 `setAlwaysOnTop(true, 'screen-saver')`，比普通置顶更高一级。

3. **歌词同步的开销**
   → 不做逐帧广播。主窗口只在**换歌 / 跳转 / 每 250ms** 推一次 `{歌词数组, 当前时间, 是否播放, 主题色}`，悬浮窗自己算当前句 → 静态时几乎没有开销。

4. **拖到屏幕外找不回来**
   → 开启时若存档里的坐标不在当前显示器范围内，自动回落到「主显示器工作区底部居中」；设置里有「恢复默认位置」。

### 5.3 存档结构（老存档自动兼容）

```jsonc
"settings": {
  // ...原有字段不动
  "autoLyric": true,
  "lyricWin": {
    "on": false,          // 悬浮窗是否开着
    "x": null, "y": null, // 上次位置（null = 用默认位置）
    "fontSize": 22,       // 字号
    "opacity": 85,        // 不透明度 %
    "lines": 2,           // 1 = 单行，2 = 双行
    "locked": false,      // 锁定位置
    "clickThrough": false // 鼠标穿透
  }
}
```

`migrate()` 里补默认值 —— 你现在的存档读进来不会报错，歌单收藏一条不丢。

### 5.4 自检（不回归）

`.verify/verify.js` 新增第 19 类：

- 悬浮窗必须是 `frame:false / transparent:true / alwaysOnTop:true / skipTaskbar:true`，且 `contextIsolation:true`、预加载脚本独立；
- 穿透的关闭入口必须在**主窗口**（不能在悬浮窗自己的 HTML 里）——这条写死，防止以后改回去；
- 封面 → 整页歌词 的链路完整（`#npCover` 可点 + `Ctrl+D` 存在）；
- 音量悬停展开的 DOM/CSS 结构完整；静音图标成对存在；
- 主题色会传给悬浮窗（不然悬浮窗永远是一个颜色）；
- 存档 `lyricWin` 默认值齐全，`migrate()` 有兜底。

## 七、我拍板的默认值（全部可在设置里改，不用你提前决定）

| 项 | 默认值 | 理由 |
|---|---|---|
| 悬浮歌词行数 | 双行（当前句 + 下一句） | 更接近"跟着唱"的预期 |

| 封面唱片旋转 | 开 | 播放状态一眼可见；觉得晃眼可以在设置里关 |
