## 刚做完（v2.13.0）

- [x] **倍速播放 0.75×–2.0×** —— 播放条上一个定宽的「1.0×」按钮，变调已关
- [x] **搜索本地相关性重排** —— 四项加权，把三小时合集压到原曲后面
- [x] **「真听过」才算数** —— 阈值 `min(30 秒, 时长×90%)`，拖进度条不算
- [x] **听歌统计** —— 四张卡 + 30 天柱状图 + 30 首歌 + 10 位 UP，本地歌也进榜

**搁置**：系统媒体键 / 全局快捷键。Windows 上 `globalShortcut` 是**独占**的，
开了之后别的播放器就收不到媒体键，这个取舍还没想清楚。
地基其实已经就位 —— `handleWinCmd` 里本来就有 `toggle` / `prev` / `next` 三个分支，
真要做只是"主进程注册 + 设置页开关"。

## 待做

### 听感 / 播放

- [ ] **音质档位选择** —— 现在写死取最高（`getAudioUrl` 里对 `dash.audio` 按 id 降序取第一条）。
  改成 最高可用 / 192K / 132K / 64K，播放条显示实际生效档位。
  收益：低带宽、老机器、省流量。成本：半天。
- [ ] **睡眠定时器** —— 30 / 60 / 90 分钟 + 「播完当前这首就停」，配音量渐弱。
  收益：睡前听歌刚需。成本：1 小时。
- [ ] **断点续听** —— 每首记 `pos`，下次从断点恢复（>30s 且 <90% 才恢复）。
  收益：长视频 / 长合集不用从头。成本：半天。
- [ ] **交叉淡入淡出（A/B 双播放器）** —— 两个 `<audio>` 交替，equal-power 曲线。
  要处理现有的 `playSeq` / 预防式刷新定时器，别串台。成本：2~3 天。

### 曲库 / 发现

- [ ] **第三方歌词源兜底** —— 现在是「B 站字幕 → AI 生成」，中间缺一层。
  接 [LRCLIB](https://lrclib.net)（免费、无需 key）：顺序改成 B 站字幕 → LRCLIB → AI。
  顺带补「±0.5s 微调」和「手动搜歌词改绑」。成本：1~2 天。
- [ ] **外部歌单导入（网易云 / QQ 音乐）** —— 拉外部歌单的 歌名+歌手，逐条在搜索层
  找最佳匹配，落成本地歌单。建议先做半自动（搜出来让用户确认一遍）。
  收益：拉新最强的一条。成本：3~5 天。
- [ ] **AI 口味推荐** —— 复用 `ai-lyrics.js` 的 Key / 加密 / 缓存基建，
  让模型只吐检索关键词，再用它去搜、再本地重排。**绝不让模型直接吐歌名**（必编）。
  和「相关性重排」共用骨架。成本：2~3 天。

### 数据 / 备份

- [ ] **整包备份导出 / 导入** —— zip 打包 歌单 / 收藏 / 设置 / 统计 / 背景图，
  导入时校验版本号。成本：半天。

### 外观 / 观感

- [ ] **封面主色提取 → 主题自适应** —— canvas 取 64×64 缩略图算中位色，
  加一套「跟随封面」主题。收益：视觉惊艳。成本：半天。
- [ ] **标题元数据清洗** —— 正则黑/白名单剥掉【MV】【中字】【4K】这类噪声，
  保留 Hi-Res / 杜比标识。成本：半小时。

### 进阶 / 需要单独评估

- [ ] **均衡器 + 音效** —— Web Audio 的 `BiquadFilterNode` 串 8 段。
  注意自定义协议（`local-protocol.js`）的 CORS。投入产出比一般，建议只做 5 个预设。
  成本：2 天。
- [ ] **局域网远程控制** —— mDNS + TCP 配对 + 二维码，手机遥控电脑。
  工程量最大，收益看使用场景。成本：1 周以上。
