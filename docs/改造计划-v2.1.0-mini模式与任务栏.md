## 一、参考资料（别人是怎么做的）

### 1.1 mini 模式

主流音乐软件（网易云、QQ 音乐、酷狗）的做法**都一样**：**不新开窗口**，而是把主窗口缩小 + 换一套界面布局，右上角留一个"还原"按钮回到完整模式。

- 好处：播放状态、进度、音量、歌词、背景**全都原地不动**，不用在两个窗口之间同步（那是最容易出 bug 的地方）。
- 你项目里**已经有现成的同类先例**：桌面歌词窗（`src/main.js:598`）就是"第二个窗口"，它的代价是要靠 IPC 推歌词、推进度、推样式（`lyric:push` / `lyric:style` / `lyric:resize` 一共 6 个通道）。mini 模式**没必要**再走一遍这套。

### 1.2 图4：任务栏缩略图上的按钮 + 专辑封面

搜到的参考文章：[《Windows | 模仿网易云任务栏实现自定义按钮及缩略图》](https://juejin.cn/post/7304562756430839846)（作者 庄周de蝴蝶，2023-11）。它把网易云的做法完整拆了一遍，两个关键点：

| 效果 | 网易云用的 Win32 接口 | Electron 有没有 |
|---|---|---|
| 缩略图底部那排按钮（上一首 / 暂停 / 下一首 / 喜欢） | `ITaskbarList3::ThumbBarAddButtons` | ✅ **有** —— `win.setThumbarButtons()` |
| 缩略图内容换成**专辑封面**（而不是窗口截图） | `DwmSetIconicThumbnail` + `DwmSetWindowAttribute(DWMWA_FORCE_ICONIC_REPRESENTATION)` | ❌ **没有** |

Electron 官方那页「[任务栏自定义](https://www.electronjs.org/zh/docs/latest/tutorial/windows-taskbar)」也印证了：它只提供**缩略图工具栏**（按钮），没有"自定义缩略图内容"。

Electron 这边最接近的替代是 `win.setThumbnailClip(region)` —— 官方说明是"**设置悬停在任务栏窗口上时显示的缩略图**要截取窗口的哪个区域"。也就是说：它不能塞一张任意图片，但**能裁窗口的一块**。所以如果 mini 模式下窗口里正好有一块封面，裁那一块，悬停看到的就基本是封面。

### 1.3 图5：任务栏按钮右键菜单（JumpList）

Electron 官方文档对 JumpList 的「任务（Tasks）」有一段明确限制（原文大意）：

> 任务应当**与上下文无关**，因为它**不需要程序运行就可以工作**……强烈推荐任务列表内容是**静态的**。
> MacOS 里的 dock menu 是菜单项，然而 Windows 里的 user tasks **只是一个快捷方式** —— 用户点它，程序会以**特定参数**启动。

再对照你的图5：它有**两个子菜单**（「列表循环 ▸」「完整模式 ▸」），第一项还是**当前正在播的歌名**（动态内容）。

→ 所以图5 **不可能是** JumpList。它只能是**托盘图标（系统托盘）的右键菜单** —— Electron 的 `Tray` + `setContextMenu(nativeMenu)` 支持图标、子菜单、动态项，能 100% 还原图5。

### 1.4 托盘菜单

Electron 官方 [Tray 文档](https://www.electronjs.org/zh/docs/latest/api/tray)：`new Tray(icon)` + `tray.setContextMenu(menu)` + `tray.setToolTip(...)`，菜单就是普通的 `Menu.buildFromTemplate`，**支持 `submenu` / `type: 'separator'` / `enabled: false`**。图5 里所有元素都能对应上。

## 三、方案 A：mini 模式（图1 + 图2 + 图3）

### 3.1 总体思路

**同一个窗口，不新建**。三步：

1. **记住**进 mini 之前的窗口位置和大小（`win.getBounds()`）。
2. 加 `body.mini` 类 → CSS 换布局；同时把窗口缩小（`setBounds`）并限制尺寸（`setMinimumSize` / `setMaximumSize` / `setResizable(false)`）。
3. 退出 mini 时把 `body.mini` 去掉、窗口**还原到记住的位置和大小**。

### 3.2 mini 收起态（对应图2）

窗口尺寸建议 **420 × 132**（可拖边缘调整先不做，`resizable: false`，免得拖乱了布局）。

```
┌────────────────────────────────────────────────┐
│ ┌──────┐    ⏮  ⏸  ⏭      ♡  🔊  ☰      ✕ ▢  │   ← 整条可拖动
│ │ 封面 │                                       │
│ └──────┘                                       │
│  誰よりも - KG/菅原纱由理（THE SxPLAY）        │   ← 歌名（超长省略号）
└────────────────────────────────────────────────┘
```

对应关系（全部复用现成元素，不新造控件）：

| 图2 里的东西 | 用项目里哪个 |

| 封面 | `#npCover`（`index.html:294`） |
| ⏮ ⏸ ⏭ | `#btnPrev` / `#btnPlay` / `#btnNext`（`index.html:311-313`） |

## 四、方案 B：任务栏缩略图上的三个按钮（图4）

### 4.1 能做的部分

`src/main.js` 里，窗口创建后加：

```js
const { nativeImage } = require('electron');
const ic = (n) => nativeImage.createFromPath(path.join(__dirname, 'assets', n));

mainWindow.setThumbarButtons([
  { tooltip: '上一首', icon: ic('thumb-prev.png'),  click: () => sendCmd('prev') },
  { tooltip: '播放/暂停', icon: ic(isPlaying ? 'thumb-pause.png' : 'thumb-play.png'), click: () => sendCmd('toggle') },
  { tooltip: '下一首', icon: ic('thumb-next.png'),  click: () => sendCmd('next') },
]);
```

- 按钮**点击** → 走一条新通道 `win:cmd` 发给界面，界面复用已有的 `prevTrack()` / `togglePlay()` / `nextTrack()`。
- **播放状态一变就要重设一次**（换 play/pause 图标），所以 `setThumbarButtons` 要包成一个 `refreshThumbar()` 函数，在界面推"播放状态变了"的时候调用。
- 图标要求：Windows 上是 **16×16**（高分屏可给 32×32 的 @2x），PNG 带透明通道。**必须用 `nativeImage`**，不能用 SVG。

### 4.2 做不到的部分（缩略图换成专辑封面）

- Electron **没有** `DwmSetIconicThumbnail`，所以**不能**塞一张任意图片当缩略图。
- 替代方案（我会做）：在 **mini 模式**下，用 `mainWindow.setThumbnailClip({x, y, width, height})` 把预览**裁到封面那一块**，悬停时看到的就是封面。
- 局限（如实说）：
  - 只在 **mini 模式**下裁封面才成立（完整模式下窗口里那块位置不是封面）。
  - 完整模式我就**不裁**（用默认的窗口截图预览），免得裁出一块莫名其妙的区域。
  - 而且网易云那套还额外用 `DwmSetIconicLivePreviewBitmap` 处理"悬浮在预览上的实时画面"，Electron 同样没有 —— 所以**悬浮时可能看到"封面"而不是"窗口实时画面"**，这一点和网易云不完全一样。

### 4.3 顺带能做的小东西

- `mainWindow.setThumbnailToolTip('Neko Music —— 当前歌名')`：悬停时那行提示文字，成本几乎为零。
- `mainWindow.setOverlayIcon(...)`：任务栏图标右下角的小角标（比如暂停时盖一个小暂停标）。**建议本轮不做**，容易显得花。

## 五、方案 C：托盘菜单（图5）+ 任务栏右键（JumpList）

### 5.1 新增一个托盘图标

`src/main.js` 里新建（模式照抄现有的 `createLyricWindow`，`main.js:598`）：

```js
let tray = null;
function createTray() {
  tray = new Tray(path.join(__dirname, 'assets', 'tray.png'));   // 16×16 或 32×32
  tray.setToolTip('Neko Music');
  tray.setContextMenu(buildTrayMenu());
  tray.on('click', () => { /* 单击：显示 / 隐藏主窗口 */ });
}
```

### 5.2 菜单内容（严格照图5 还原）

| 图5 里的项 | 怎么做 |
|---|---|
| （图5 没有，本轮加）**显示主窗口** | `click → mainWindow.show() + focus()` —— "缩小到任务栏"之后的总出口（见 §5.4） |
| 誰よりも - KG/菅原…（第一项） | `{ label: 当前歌名, enabled: false }` —— 动态，每次换歌重建菜单 |
| ▶ 播放 / ⏸ 暂停 | `click → sendCmd('toggle')`，标签跟着播放状态变 |
| ⏮ 上一首 | `sendCmd('prev')` |
| ⏭ 下一首 | `sendCmd('next')` |
| ↻ **列表循环 ▸** | `submenu`：列表循环 / 单曲循环 / 随机 / 顺序（**当前那个打勾** `type: 'radio'`） |
| ⧉ **完整模式 ▸** | `submenu`：完整模式 / mini 模式（`type: 'radio'`，当前那个打勾） |
| 💬 打开桌面歌词 | `click → sendCmd('lyric-open')` |
| 🔒 锁定桌面歌词 | `click → sendCmd('lyric-lock')` |
| ⚙ 设置 | `click → 显示窗口 + 打开设置面板` |
| ⏻ 退出 | `click → app.quit()` |

> 图标：`Menu` 的每一项可以带 `icon: nativeImage`。图5 里那排小图标（青绿色）需要**单独准备一组 16×16 PNG**，见 §6.2。

### 5.3 任务栏按钮右键（JumpList）—— 只能做"阉割版"

既然 JumpList 不支持子菜单，我能加的就是一组**平铺的任务**：

```
[任务]
  ▶ 播放 / 暂停
  ⏮ 上一首
  ⏭ 下一首
  ───────────
  ⧉ 切换到 mini 模式
  ⚙ 设置
```

**⚠️ 有个必须一起补的坑**：JumpList 的每一项，Windows 的实现方式是**用参数启动一个新进程**。你项目现在**没有单实例锁**（§2.3），所以点了之后会**开出第二个软件**、两个窗口抢同一个存档文件 —— 这是会出事的。

所以本轮必须同时补上：

```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) { app.quit(); }        // 第二个进程直接退出
else {
  app.on('second-instance', (_e, argv) => {
    // 从 argv 里解析出 --cmd=prev / --cmd=toggle …，转交给已经在跑的那个窗口
    // 顺便把主窗口显示出来、聚焦
  });
}
```

> 这条**不管 JumpList 做不做都得补** —— 现在用户双击两次图标也能开出两个软件。

### 5.4 关窗时的弹窗：彻底关闭 / 缩小到任务栏（你补充的那条）

**为什么必须有这个弹窗**：你项目现在的行为是**关掉主窗口 = 退出整个软件**（`main.js:690-692`，`window-all-closed` → `app.quit()`）。
一旦有了托盘图标，"点 ✕"就有了两种合理含义，而**猜错的那个一定会被骂**：

- 猜成"退出" → 用户想让它后台放歌，结果关掉了
- 猜成"缩小" → 用户以为关掉了，其实还在跑（托盘里悄悄留着）

所以第一次点 ✕ 必须**问一次**，并允许"别再问了"。

#### 弹窗长什么样

```
┌──────────────────────────────────────────┐
│  关闭 Neko Music                         │
│                                          │
│  你想怎么关？                            │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ ⏻  彻底关闭软件                    │  │   ← 退出程序
│  │    停止播放并退出，托盘图标也会消失 │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │ ⤓  缩小到任务栏                    │  │   ← 只隐藏窗口
│  │    继续在后台播放，点托盘图标能找回 │  │
│  └────────────────────────────────────┘  │
│                                          │
│  ☐ 将此选项设为默认值（以后不再询问）    │
│                                          │
│                          [ 取消 ]        │
└──────────────────────────────────────────┘
```

- 两个选项做成**两张大按钮**（带一行小字说明后果），而不是普通的"确定/取消" —— 因为你零基础，得让后果一眼看懂。
- 勾了「设为默认值」→ 存档里记住这次的选择，以后 ✕ 直接照做，不再弹。
- 没勾 → 每次都弹。
- 有【取消】—— 误点 ✕ 时能退回去。

#### 两种实现，我推荐前者

| 做法 | 优点 | 缺点 |
|---|---|---|
| **A. 自绘弹窗**（推荐） | 和设置面板**同一套样式**，跟主题/毛玻璃一致；项目里已有现成的遮罩机制（`#promptMask` / `askConfirm`，`app.js` 里那套） | 要多走一次 IPC（见下面的时序） |
| B. 系统原生弹窗 `dialog.showMessageBox` | 省事，**自带 `checkboxLabel`**（原生就支持"设为默认"复选框） | 样式是 Windows 系统样式，和软件的自绘界面**不一样**，突然冒出来会显得割裂 |

我选 **A**，理由是：这个软件从标题栏到设置面板**全是自绘**的，突然弹一个系统灰框会很明显。B 作为备选，你要是觉得"系统弹窗更放心"，我就换 B。

#### 时序（走 A 的话）

```
用户点 ✕
   ↓
主进程 mainWindow.on('close') 拦下
   ↓  （此时先不进入"存盘"流程）
发给界面：win:ask-close
   ↓
界面弹出上面的窗，用户选
   ↓
界面回：win:close-choice('quit' | 'tray', remember)
   ↓
  ├─ quit → 进入**现有**的存盘流程（requestMainWindowClose → 存盘 → 关窗 → 退出）
  └─ tray → mainWindow.hide()，**不关**，播放继续；托盘图标还在
```

> ⚠️ **有一个必须做对的点**：托盘菜单里的「退出」和 JumpList 里的任务，**必须无条件真退出**，不能被这个弹窗拦住 —— 否则用户点了「退出」却只缩小了，会以为软件坏了。
> 做法：走一个 `forceQuit` 标记，绕过弹窗。

#### 设置里也能改

设置 → 常规（或外观）里加一项：

| 设置项 | 取值 | 默认 |
|---|---|---|
| **关闭主窗口时** | ○ 每次询问 ／ ○ 彻底关闭软件 ／ ○ 缩小到任务栏 | **每次询问** |

- 选「每次询问」= 每次点 ✕ 都弹那个窗（等价于没勾"设为默认"）
- 选另外两项 = 以后直接照做、不再弹（等价于勾了"设为默认"）
- 弹窗里勾了「设为默认值」→ 这一项**自动跟着变**，两边永远同步（同一个存档字段）

**存档**：新增 `settings.close = { action: 'ask' | 'quit' | 'tray' }`，**缺省 `'ask'`**。
⚠️ 这里有个取舍要你拍板：缺省 `'ask'` 意味着**老用户升级后第一次关窗会看到新弹窗**（多一步）。另一种是缺省 `'quit'`（老用户无感、保持"关窗即退出"，只有自己去设置里改才会看到弹窗）。我**倾向 `'ask'`** —— 因为托盘图标是这轮新加的，第一次问一下最不容易出误会；你要是想"老用户无感"，我改成 `'quit'`。

#### 顺带要处理的三个小地方

1. **缩小到任务栏之后怎么找回**：点托盘图标 / 双击托盘 / 托盘菜单第一项「显示主窗口」（§5.2 那张表要加一行）。
2. **缩小到任务栏时，mini 模式怎么办**：保持原样（不强制切回完整模式）。
3. **`window-all-closed` 那条**：选了"缩小到任务栏"时窗口是 `hide()` 不是 `close()`，所以 `window-all-closed` **不会**触发，`app.quit()` 也不会被调用 —— 这条逻辑天然正确，不用改。但**要加一句断言**守住它（免得以后有人改成 `close()` 就把后台播放弄没了）。

## 八、已知取舍（先说清楚，不藏）

1. **缩略图换成专辑封面做不到 100% 像网易云**（§4.2）—— Electron 缺 DWM 那个接口。我只能"裁窗口里的封面区域"近似。
2. **mini 模式不新建窗口**，所以 mini 期间**主窗口就是唯一的窗口** —— 任务栏图标、缩略图按钮、托盘菜单全都作用在它身上，这点正好是你想要的。
3. **托盘菜单要"跟着状态重建"**：歌名、播放/暂停标签、当前播放模式、当前是不是 mini —— 这四项一变就得 `tray.setContextMenu(buildTrayMenu())` 重设一次。菜单是原生的，**不能像网页那样局部刷新**。
4. **托盘图标需要一个图标文件**，项目现在**一个图标都没有**（连窗口图标都没有）。我会生成一个简单的（一只猫的耳朵 + 音符，或者纯音符），你要是想自己给图，直接说。
5. **JumpList 是"阉割版"**（无子菜单），这是 Windows 的限制，不是偷懒。
6. **"关窗即退出"这个老习惯被改了**（§5.4）—— 以后点 ✕ 会**先问一次**。这是加托盘的必然代价；如果你觉得多这一步烦，我把缺省设成「彻底关闭软件」，只有主动去设置里改的人才会看到弹窗。
7. **mini 模式下"背景模糊 / 面板不透明度"这些设置照旧生效**，但 mini 窗很小，背景基本被封面和控件盖住 —— 如果你希望 mini 模式强制用"纯色底"（更清爽、也省一点显卡），说一声，我加一条。
