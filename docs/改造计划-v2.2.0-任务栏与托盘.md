## 一、参考资料（别人是怎么做的）

### 1.1 图4：任务栏缩略图上的按钮 + 专辑封面

参考文章：[《Windows | 模仿网易云任务栏实现自定义按钮及缩略图》](https://juejin.cn/post/7304562756430839846)（作者 庄周de蝴蝶，2023-11）。它把网易云的做法完整拆了一遍：

| 效果 | 网易云用的 Win32 接口 | Electron 有没有 |
|---|---|---|
| 缩略图底部那排按钮（上一首 / 暂停 / 下一首 / 喜欢） | `ITaskbarList3::ThumbBarAddButtons` | ✅ **有** —— `win.setThumbarButtons()` |
| 缩略图内容换成**专辑封面**（而不是窗口截图） | `DwmSetIconicThumbnail` + `DwmSetWindowAttribute(DWMWA_FORCE_ICONIC_REPRESENTATION)` | ❌ **没有** |
| 悬浮在预览上时的"实时画面" | `DwmSetIconicLivePreviewBitmap` | ❌ **没有** |

Electron 官方那页「[任务栏自定义](https://www.electronjs.org/zh/docs/latest/tutorial/windows-taskbar)」也印证了：它只提供**缩略图工具栏**（按钮），没有"自定义缩略图内容"。

最接近的替代是 `win.setThumbnailClip(region)` —— 官方说明是"**设置悬停在任务栏窗口上时显示的缩略图**要截取窗口的哪个区域"。它不能塞任意图片，但**能裁窗口的一块**。

### 1.2 图5：为什么它一定不是 JumpList

Electron 官方文档对 JumpList 的「任务（Tasks）」有一段明确限制（原文大意）：

> 任务应当**与上下文无关**，因为它**不需要程序运行就可以工作**……强烈推荐任务列表内容是**静态的**。
> MacOS 里的 dock menu 是菜单项，然而 Windows 里的 user tasks **只是一个快捷方式** —— 用户点它，程序会以**特定参数**启动。

再对照图5：它有**两个子菜单**（「列表循环 ▸」「完整模式 ▸」），第一项还是**当前正在播的歌名**（动态内容）。

→ 所以图5 **不可能是** JumpList，只能是**托盘图标（系统托盘）的右键菜单**。

### 1.3 托盘菜单

Electron 官方 [Tray 文档](https://www.electronjs.org/zh/docs/latest/api/tray)：`new Tray(icon)` + `tray.setContextMenu(menu)` + `tray.setToolTip(...)`，菜单就是普通的 `Menu.buildFromTemplate`，**支持 `submenu` / `type: 'separator'` / `enabled: false` / `type: 'radio'`**。图5 里所有元素都能对应上。

## 三、方案 A：任务栏缩略图上的三个按钮（图4）

### 3.1 能做的部分

`src/main.js` 里，窗口创建后加：

```js
const { nativeImage } = require('electron');
const ic = (n) => nativeImage.createFromPath(path.join(__dirname, 'assets', n));

mainWindow.setThumbarButtons([
  { tooltip: '上一首',     icon: ic('thumb-prev.png'),  click: () => sendCmd('prev') },
  { tooltip: '播放/暂停',  icon: ic(isPlaying ? 'thumb-pause.png' : 'thumb-play.png'), click: () => sendCmd('toggle') },
  { tooltip: '下一首',     icon: ic('thumb-next.png'),  click: () => sendCmd('next') },
]);
```

- 按钮**点击** → 走一条新通道 `win:cmd` 发给界面，界面复用已有的 `prevTrack()` / `togglePlay()` / `nextTrack()`。
- **播放状态一变就要重设一次**（换 play/pause 图标），所以包成一个 `refreshThumbar()`，在界面推"播放状态变了"时调用。
- 图标要求：Windows 上是 **16×16**（高分屏可给 32×32 的 @2x），PNG 带透明通道。**必须用 `nativeImage`**，不能用 SVG。

> ✅ **参考项目 biu 的写法和我们几乎一模一样**（它的 `electron/windows/thumbar.ts`）：
> 同样是 `setThumbarButtons([{ tooltip:'上一首', icon }, { tooltip: isPlaying ? '暂停' : '播放', icon }, { tooltip:'下一首', icon }])`，
> 同样在**播放状态变化时**重设一次（`ipcMain.on(channel.player.state, (_, isPlaying) => ensureThumbBar(!!isPlaying))`），
> 连"按播放状态换 play/pause 图标"这个细节都撞上了，图标也是 4 个 PNG。
> → **说明这条方案是对的，可以放心做**（细节见 `docs/参考实现研究-biu.md` §2.1 的对照）。

### 3.2 做不到的部分 + 替代方案（缩略图换成专辑封面）

- Electron **没有** `DwmSetIconicThumbnail`，所以**不能**塞一张任意图片当缩略图。
- **替代方案（我会做）**：在 **mini 模式**下，用 `mainWindow.setThumbnailClip({x, y, width, height})` 把预览**裁到封面那一块** —— 悬停时看到的就是封面。
- **局限（如实说）**：
  - 只在 **mini 模式**下裁封面才成立（完整模式下窗口里那块位置不是封面）。**这是本轮的实现依赖 v2.1.0 mini 模式的原因。**
  - 完整模式**不裁**（用默认的窗口截图预览），免得裁出一块莫名其妙的区域。
  - 网易云那套还额外用 `DwmSetIconicLivePreviewBitmap` 处理"悬浮在预览上的实时画面"，Electron 同样没有 —— 所以**悬浮时可能看到"封面"而不是"窗口实时画面"**，这一点和网易云不完全一样。
- ⚠️ **参考项目 biu 也没做这一步**（它只做了 `setThumbarButtons`）—— 所以"裁封面"这一条**没有现成先例可抄**，
  仍然是我根据官方 API 文档推断的做法。**真机上要重点验证**（见 §8 C-1）；万一效果不好，退路是"不裁，保持默认窗口预览"。

> ⚠️ **明确不做**：biu 在进 mini 时是**另开一个 `skipTaskbar: true` 的小窗**（详见 `docs/参考实现研究-biu.md` §3.1）。
> 我们**不学这个** —— 它会让任务栏图标消失，而图4 的三个按钮**正是挂在任务栏图标上的**，两条需求会直接打架。
> 我们沿用 v2.1.0 的"同一个窗口缩小"，任务栏图标一直在。

### 3.3 顺带能做的小东西

- `mainWindow.setThumbnailToolTip('Neko Music —— 当前歌名')`：悬停时那行提示文字，成本几乎为零。
- `mainWindow.setOverlayIcon(...)`：任务栏图标右下角的小角标（比如暂停时盖一个小暂停标）。**建议本轮不做**，容易显得花。

### 3.4 顺手加固：安全与崩溃兜底（从 biu 学到的）

参考项目 biu 有两条我们**目前没有**的兜底，本轮一起补（都写在 `src/main.js` 的 `createWindow()` 内）：

```js
// ① 禁止开新窗口。
//    target="_blank" / window.open / 中键点击都可能弹出 Electron 原生新窗口 ——
//    那个窗口没有 preload、没有我们的 CSP 管控，等于开了个后门。
//    Neko 的外链走的是 shell.openExternal（main.js:367），所以 deny 掉不影响正常功能。
mainWindow.webContents.setWindowOpenHandler(() => ({ action: 'deny' }));

// ② 主进程崩溃时主动退出（这条在"加了托盘"之后变得重要）。
//    主进程一旦崩了但没退出，托盘图标会一直留着、点它也没反应，用户会以为"软件卡死了"。
//    主动退出比留个僵尸图标好。
process.on('uncaughtException', (err) => {
  console.error('[uncaughtException]', err);
  app.quitting = true;
  app.quit();
});
```

| 加固项 | 为什么值得做 |
|---|---|
| `setWindowOpenHandler` deny | 堵住"原生新窗口"这个后门；外链本来就走 `shell.openExternal`，不受影响 |
| `uncaughtException` → `app.quit()` | 有托盘之后，主进程崩溃会**留下一个没反应的托盘图标**，比直接退出更让人困惑 |

> 关于 `hookWindowMessage(0x0116)` / 拦 Ctrl+R / 拦右键菜单这三处：**已经在 v2.1.0 的 §6.2 一起做了**，本轮不重复。

## 四、方案 B：托盘菜单（图5）+ 任务栏右键（JumpList）

### 4.1 新增一个托盘图标

`src/main.js` 里新建（写法参照现有的 `createLyricWindow`，`main.js:598`）。
下面这段**吸收了参考项目 biu 的四处细节**（见 `docs/参考实现研究-biu.md` §2.5）：

```js
let tray = null;
let trayIcon = null;   // 图标对象缓存下来，别每次重建都重新读盘

function createTray() {
  // ★ 细节①：Windows 上用 .ico（ico 里可以塞多分辨率，系统按 DPI 自己挑，比 PNG 清晰）
  const trayIconPath = path.join(__dirname, 'assets', 'tray.ico');
  trayIcon = nativeImage.createFromPath(trayIconPath);

  // ★ 细节②：图标加载失败要"吭声" —— 路径写错时托盘会静默不出现，非常难查
  if (trayIcon.isEmpty()) console.error('[tray] 图标没加载出来：' + trayIconPath);

  // ★ 细节③：创建前先把旧的销毁，避免"二次调用 / 调试时热重启"在托盘里留下两个图标
  if (tray) { tray.destroy(); tray = null; }

  tray = new Tray(trayIcon);
  tray.setToolTip('Neko Music');
  tray.setContextMenu(buildTrayMenu());
  tray.on('click', () => { /* 单击：显示 / 隐藏主窗口 */ });
}

// ★ 细节④：退出前销毁托盘图标，否则它会残留在托盘里，直到鼠标划过去才消失
app.on('will-quit', () => {
  if (tray) { tray.destroy(); tray = null; }
});
```

### 4.2 菜单内容（严格照图5 还原）

| 图5 里的项 | 怎么做 |
|---|---|
| （图5 没有，本轮加）**显示主窗口** | `click → mainWindow.show() + focus()` —— "缩小到任务栏"之后的总出口（见 §5） |
| 誰よりも - KG/菅原…（第一项） | `{ label: 当前歌名, enabled: false }` —— 动态，每次换歌重建菜单 |
| ▶ 播放 / ⏸ 暂停 | `click → sendCmd('toggle')`，标签跟着播放状态变 |
| ⏮ 上一首 | `sendCmd('prev')` |
| ⏭ 下一首 | `sendCmd('next')` |
| ↻ **列表循环 ▸** | `submenu`：列表循环 / 单曲循环 / 随机 / 顺序（**当前那个打勾** `type: 'radio'`） |
| ⧉ **完整模式 ▸** | `submenu`：完整模式 / mini 模式（`type: 'radio'`，当前那个打勾） |
| 💬 打开桌面歌词 | `click → sendCmd('lyric-open')` |
| 🔒 锁定桌面歌词 | `click → sendCmd('lyric-lock')` |
| ⚙ 设置 | `click → 显示窗口 + 打开设置面板` |
| ⏻ 退出 | `click → app.quit()`（走 `app.quitting` 标记真退出，见 §5.4） |

> **菜单要"跟着状态重建"**：歌名、播放/暂停标签、当前播放模式、当前是不是 mini —— 这四项一变就得 `tray.setContextMenu(buildTrayMenu())` 重设一次。原生菜单**不能像网页那样局部刷新**。
>
> 📌 **参考项目 biu 的托盘菜单比图5 简单**（只有"播放/暂停 · 上一曲 · 下一曲 · 显示/隐藏 · 设置 · 退出"，**没有子菜单**）——
> 所以图5 那种带「列表循环 ▸」「完整模式 ▸」的菜单，**它没有可抄的**，得我们自己用 `submenu` + `type: 'radio'` 写（Electron 的 `Menu` 支持这两个）。

### 4.3 任务栏按钮右键（JumpList）—— 只能做"阉割版"

既然 JumpList 不支持子菜单，能加的就是一组**平铺的任务**：

```
[任务]
  ▶ 播放 / 暂停
  ⏮ 上一首
  ⏭ 下一首
  ───────────
  ⧉ 切换到 mini 模式
  ⚙ 设置
```

**⚠️ 有个必须一起补的坑**：JumpList 的每一项，Windows 的实现方式是**用参数启动一个新进程**。项目现在**没有单实例锁**（§2.1），点了之后会**开出第二个软件**、两个窗口抢同一个存档文件 —— 这是会出事的。

所以本轮必须同时补上：

```js
const gotLock = app.requestSingleInstanceLock();
if (!gotLock) {
  app.quit();                       // 第二个进程直接退出
} else {
  app.on('second-instance', (_e, argv) => {
    // 从 argv 里解析出 --cmd=prev / --cmd=toggle …，转交给已经在跑的那个窗口
    if (mainWindow.isMinimized()) mainWindow.restore();   // ★ 这一条容易漏（见下）
    if (!mainWindow.isVisible()) mainWindow.show();
    mainWindow.focus();
  });
}
```

> ★ **`isMinimized()` 那一条是从 biu 学来的**（`electron/main.ts`）—— 只 `show()` **不够**：
> 窗口处于"最小化"状态时，`show()` 不会把它还原出来，用户点了两次图标却什么都没发生。
> 必须先 `restore()` 再 `show()` 再 `focus()`，三步都做才算完整（见 `docs/参考实现研究-biu.md` §2.4）。
>
> 这条**不管 JumpList 做不做都得补** —— 现在用户双击两次图标也能开出两个软件。

## 五、方案 C：关窗时的弹窗（你补充的那条）

### 5.1 为什么必须有

项目现在的行为是**关掉主窗口 = 退出整个软件**（`main.js:690-692`）。
一旦有了托盘图标，"点 ✕"就有了两种合理含义，而**猜错的那个一定会被骂**：

- 猜成"退出" → 用户想让它后台放歌，结果关掉了
- 猜成"缩小" → 用户以为关掉了，其实还在跑（托盘里悄悄留着）

所以第一次点 ✕ 必须**问一次**，并允许"别再问了"。

### 5.2 弹窗长什么样

```
┌──────────────────────────────────────────┐
│  关闭 Neko Music                         │
│                                          │
│  你想怎么关？                            │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ ⏻  彻底关闭软件                    │  │   ← 退出程序
│  │    停止播放并退出，托盘图标也会消失 │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │ ⤓  缩小到任务栏                    │  │   ← 只隐藏窗口
│  │    继续在后台播放，点托盘图标能找回 │  │
│  └────────────────────────────────────┘  │
│                                          │
│  ☐ 将此选项设为默认值（以后不再询问）    │
│                                          │
│                          [ 取消 ]        │
└──────────────────────────────────────────┘
```

- 两个选项做成**两张大按钮**（各带一行小字说明后果），而不是普通的"确定/取消" —— 得让后果一眼看懂。
- 勾了「设为默认值」→ 存档记住这次的选择，以后 ✕ 直接照做、不再弹。
- 没勾 → 每次都弹。
- 有【取消】—— 误点 ✕ 时能退回去。

### 5.3 两种实现，我推荐前者

| 做法 | 优点 | 缺点 |
|---|---|---|
| **A. 自绘弹窗**（推荐） | 和设置面板**同一套样式**，跟主题/毛玻璃一致；项目里已有现成的遮罩机制（`#promptMask` / `askConfirm` 那套） | 要多走一次 IPC（见 §5.4） |
| B. 系统原生弹窗 `dialog.showMessageBox` | 省事，**自带 `checkboxLabel`**（原生就支持"设为默认"复选框） | 样式是 Windows 系统样式，和软件的自绘界面**不一样**，突然冒出来显得割裂 |

选 **A**，理由是：这个软件从标题栏到设置面板**全是自绘**的，突然弹一个系统灰框会很显眼。B 作为备选（§11 Q3）。

### 5.4 时序（走 A 的话）

```
用户点 ✕
   ↓
主进程 mainWindow.on('close') 拦下（preventDefault）
   ↓
看 settings.close.action：
   ├─ 'quit' → 直接进入**现有**的存盘流程（requestMainWindowClose → 存盘 → 关窗 → 退出）
   ├─ 'tray' → mainWindow.hide()，**不关**，播放继续；托盘图标还在
   └─ 'ask'  → 发给界面：win:ask-close
                 ↓
              界面弹出上面的窗，用户选
                 ↓
              界面回：win:close-choice('quit' | 'tray', remember)
                 ↓
               ┌─ quit → 进入**现有**的存盘流程（同上）
               └─ tray → mainWindow.hide()
```

### 5.4.1 "正在退出"的标记：用 `app.on('before-quit')`，不用自定义 `forceQuit` ⭐

**必须做对的一点**：托盘菜单里的「退出」、JumpList 里的任务、`Ctrl+Q`、系统关机……
**都必须无条件真退出**，不能被这个弹窗 / `hide()` 拦住 —— 否则用户点了「退出」却只缩小了，会以为软件坏了。

我原来的写法是"在托盘退出那里手动设一个 `forceQuit` 标记"—— 但那**只能覆盖我想到的那一条路径**。
参考项目 biu 的做法更稳（`electron/main.ts`）：

```js
// ★ 每一次"真退出"都会先经过这里：托盘退出、Ctrl+Q、系统关机、任务管理器结束、任何 app.quit()
app.on('before-quit', () => { app.quitting = true; });
```

然后 `close` 处理里：

```js
mainWindow.on('close', (event) => {
  if (allowCloseOnce) { allowCloseOnce = false; return; }   // 存盘握手完成后的那一次真关，放行
  event.preventDefault();                                   // 其余一律先拦下

  // ① 正在退出（上面那个标记）→ 跳过弹窗、跳过 hide，直接进存盘流程
  // ② 用户设置成"彻底关闭"   → 同上
  if (app.quitting || settings.close.action === 'quit') { requestMainWindowClose(); return; }
  // ③ 用户设置成"缩小到任务栏" → 只隐藏
  if (settings.close.action === 'tray') { mainWindow.hide(); return; }
  // ④ 缺省 'ask' → 问一次
  mainWindow.webContents.send('win:ask-close');
});
```

> ⚠️ **Neko 和 biu 有一处关键差别，不能照抄它的 `close` 分支**：
> biu 关窗前**不需要存盘**（它用的是实时写入的 store），所以它写的是 `if (app.quitting) return;` —— **直接放行关闭**。
> Neko 关窗前要做一次"存盘握手"（`requestMainWindowClose`，`main.js:149-171`）。
> 所以我们必须改成：**真退出时仍然走存盘握手**（`requestMainWindowClose()`），只是**跳过弹窗、跳过 `hide()`**。
> 换句话说：`before-quit` 标记的作用是"**跳过询问**"，不是"跳过存盘"。

### 5.5 设置里也能改

设置里加一项：

| 设置项 | 取值 | 默认 |
|---|---|---|
| **关闭主窗口时** | ○ 每次询问 ／ ○ 彻底关闭软件 ／ ○ 缩小到任务栏 | **每次询问** |

- 选「每次询问」= 每次点 ✕ 都弹窗（等价于没勾"设为默认"）
- 选另外两项 = 以后直接照做、不再弹（等价于勾了"设为默认"）
- 弹窗里勾了「设为默认值」→ 这一项**自动跟着变**，两边永远同步（同一个存档字段）

**存档**：新增 `settings.close = { action: 'ask' | 'quit' | 'tray' }`，**缺省 `'ask'`**。

> ⚠️ **这里有个取舍要你拍板**（§11 Q4）：缺省 `'ask'` 意味着**老用户升级后第一次关窗会看到新弹窗**（多一步）。
> 另一种是缺省 `'quit'`（老用户无感、保持"关窗即退出"，只有自己去设置里改才会看到弹窗）。
> 我**倾向 `'ask'`** —— 托盘图标是本轮新加的，第一次问一下最不容易出误会。

### 5.6 顺带要处理的三个小地方

1. **缩小到任务栏之后怎么找回**：点托盘图标 / 双击托盘 / 托盘菜单第一项「显示主窗口」（§4.2 那张表里已经加了）。
2. **缩小到任务栏时，mini 模式怎么办**：保持原样（不强制切回完整模式）。
3. **`window-all-closed` 那条**：选"缩小到任务栏"时窗口是 `hide()` 不是 `close()`，所以 `window-all-closed` **不会**触发、`app.quit()` 也不会被调用 —— 这条逻辑天然正确、不用改。但要**加一句断言**守住它（免得以后有人改成 `close()`，就把后台播放弄没了）。

## 六、需要准备的小图标

**全部用脚本生成，不手画、不引入新依赖** —— 手法和 `.verify/test-round9.js` 里的 `solidPng()` 一样（纯 Node 手搓 PNG：`zlib.deflateSync` + CRC32 + IHDR/IDAT/IEND）。

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `assets/tray.ico` | **内含 16×16 + 32×32 两档** | 托盘图标（图5 的入口） |
| `assets/thumb-prev.png` / `thumb-play.png` / `thumb-pause.png` / `thumb-next.png` | 16×16 | 图4 那三个按钮 |
| `assets/menu-*.png` | 16×16 ×约 10 个 | 图5 菜单里那排小图标（**可选**，不加就是没图标） |

**为什么托盘用 `.ico` 而不是 `.png`**（从 biu 学来的，见研究笔记 §2.5）：
`.ico` 是"多分辨率容器"，系统会按当前 DPI 自己挑最合适的一档 —— 125% / 150% 缩放下比单张 PNG 清晰。
（PNG 也能用，只是高分屏会有点糊。）

> **`.ico` 怎么用纯 Node 生成**（不引入新依赖）：ICO 的容器格式很简单 ——
> 6 字节文件头 + 每个尺寸 16 字节的目录项 + 后面直接跟 **PNG 数据**（Vista 以后的 ICO 允许内嵌 PNG）。
> 我们已经有 `solidPng()` 能搓出 PNG，只要再加一个 `icoWrap([png16, png32])` 把两张 PNG 塞进 ICO 容器即可（约 40 行）。
>
> 窗口图标 `assets/app.png` 已经在 **v2.1.0** 做了，本轮不重复。

## 九、已知取舍（先说清楚，不藏）

1. **缩略图换成专辑封面做不到 100% 像网易云**（§3.2）—— Electron 缺 DWM 那个接口，只能"裁窗口里的封面区域"近似。
2. **托盘菜单是原生的、不能局部刷新**（§4.2）—— 状态一变就要整个重建一次。
3. **JumpList 是"阉割版"**（无子菜单），这是 Windows 的限制，不是偷懒。
4. **"关窗即退出"这个老习惯被改了**（§5）—— 以后点 ✕ 会**先问一次**。这是加托盘的必然代价。
5. **托盘图标必须有一个图标文件**（§6），我会生成一个简单的（音符 / 猫耳）。你想自己给图，直接说。
6. **本轮不改"关掉窗口后软件还在后台"这个新语义本身** —— 选「缩小到任务栏」时软件确实还在跑，这是你要的效果，但要在弹窗里把那行小字写清楚（§5.2）。
7. **明确不学参考项目 biu 的"独立小窗"做法**（`skipTaskbar: true` 的 mini 窗口）—— 它会让任务栏图标消失，
   而图4 的三个按钮正挂在任务栏图标上（详见 `docs/参考实现研究-biu.md` §3.1）。我们沿用 v2.1.0 的"同一个窗口缩小"。
