## 关键技术约定（踩过坑的，别重犯）

- **IPC 信封**：主进程 `handle()` 统一返回 `{ok, data}`，渲染层必须走 `api('xxx')` 解包；直接调 `window.neko.*` 会拿到外壳 —— 这曾经导致"设置关掉就重置"的 bug，找了两轮。
- **`window.prompt` / `confirm` 在 Electron 里没实现**（返回 null，静默失效）。项目自带 `#promptMask` 模态框，用 `askName/askConfirm/pickPlaylistFor`。
- **CSS 陷阱**：`box-sizing:border-box` + `inset:0` + 百分比 padding 会让 `clientHeight` 膨胀（曾导致歌词浮层恒偏 191px）。要撑高度用伪元素 spacer。
- **CSS 颜色语法陷阱**：`rgba(var(--x) / a)` 是**非法写法**，会被整条丢弃且**不报错**（v2.0.0 修过，波及 40 处半透明主题色）。正确写法：`rgb(var(--x) / a)`，或 `rgb(var(--x) / var(--a))`。静态自检第 46 类专门守这个。
- **Electron 离屏测试**：跑测试必须 `env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron xxx.js`（否则会当 Node 跑）；用 `offscreen:true` + `webContents.sendInputEvent` 合成鼠标事件 + `capturePage` 截图；electron 跑完不退出，命令前加 `timeout N` 收尾。
- **离屏软件光栅"不重绘"的坑（v2.0.2 踩得最深）**：`capturePage()` 在离屏下取不到新帧有**两条**路径 —— ① 页面静止后不再产帧；② **滚动容器（`overflow-y:auto`，自带合成层）"改可见性"走的是"合成器把整个滚动图层隐藏"这条优化，根本不重新光栅化** —— DOM 里计算样式明明是 `hidden`，画面上照旧，**连拍多少张都是同一张旧图层**（实测跨多次运行、跨 CSS 三版，png md5 完全不变）。对策：**藏子元素**（强制内容真正重绘成空）+ **另开新窗口**拍照 + 截图前给容器子元素加/撤一次行内 `visibility`（`nudge()`）逼重光栅化。**另外"看图工具"有缓存**（同一路径重复读会返回 "Image unchanged"），最终结论一律用 `capturePage().getBitmap()` dump 裸位图后**直接数像素**断案。
- **B 站接口**：搜索接口不返回分P数，用启发式猜（时长 ≥30min + 标题关键词）；点开才 `getVideoInfo`。UP 主页走 wbi 签名的 `space/wbi/arc/search`，**对未登录/风控敏感**，沙箱里大概率失败 —— 这类只能靠我本机验证，你要做优雅失败提示（引导去 ⚙ 设置填 Cookie）。
- **存档**：在 `%APPDATA%\neko-music\`，**不进 Git**；新增字段一律给缺省值 = 旧行为，**旧存档零迁移**。已扩过的字段：`settings.playMode`、`collectOff`、`collectParts`、`settings.bg`（v1.8.0 扩成 `{file, kind, dim, blur, video:{muted,loop,speed}}`，v1.9.0 再加 `perfLite` / `pauseOnBlur`，缺省 = `true`）、`settings.glass.mode`（v2.0.0，`plain`/`prebake`/`live`，缺省 `prebake`）、`settings.glass.frameAlpha`（v2.0.2，缺省 `0.12`；旧的 `glass.alpha` 退役，**故意**让老存档也走新默认）。
- **替换元素（replaced element）的坑**：`<video>` / `<img>` 这类元素，光写 `position:absolute; inset:0` **不会撑满** —— 浏览器优先用它的**固有尺寸**，`right`/`bottom` 被忽略。必须显式 `width:100%; height:100%`，再配 `object-fit:cover` 才等比铺满。v1.9.0 的"窗口缩小只剩左上角"就是这个根因。
- **`backdrop-filter` / `filter` 的代价**：模糊**正在播放的视频**=每帧重新采样+重模糊。真省显卡的写法是 `backdrop-filter: none`（**不是 `blur(0px)`** —— 那仍会把背景拷进贴图）。静态图模糊一次就缓存，可以放心留。
- **prebake 毛玻璃**：默认档用 `buildGlassImage()` 预烘焙一张糊好的壁纸图（`--glass-img`，data:URL），贴在标题栏/侧栏/顶栏/播放条背景上。**它绕过了底图层**，所以任何"作用在底图上的效果"（如压暗）都必须**同时**加进这四块面板，否则会出现"只有内容区变了、面板没变"的 bug（v2.0.0 背景压暗就踩过）。**v2.0.2 起四块框架的压暗量统一由 `--frame-a` 一个变量控制**（默认 0.12），别再给某一块单独写偏移量 —— 那正是 v2.0.2 要修的"四块深浅不一"。视频背景下拿不到 `has-imgbg`，四块会退回基础规则，也**必须**一起读 `--frame-a`。
- **`bg://` 资源失败会被缓存**：文件**必须在 `loadFile()` 之前**就位，否则首次 404 会被缓存，之后设同一个 URL 也不会重试（曾导致演示截图全黑，排查手法是 `capturePage().getBitmap()` 逐像素采样）。
- **★ Windows 上 `setResizable(false)` 会把 min/max 一起钉死成"当前尺寸"**（v2.1.0 踩到）：这就是"不可缩放"的实现方式。所以**退出 mini 还原尺寸时，`setResizable(true)` 必须放在最前面** —— 不解开它，后面的 `setMinimumSize` / `setMaximumSize` **全都会被无视**，表现是"点了 ▢ 窗口还原不回去、卡在 mini 那个大小上"。另外**顺序**还要求"先放大 max、再调 min"（反了会出现瞬时 `min > max`，那一句被丢掉）。记"还原目标"要用 `getNormalBounds()`（窗口最大化时 `getBounds()` 给的是全屏尺寸）。
- **★ `flex-wrap` 是"先按假设尺寸断行、再收缩"的**（v2.1.0 踩到）：mini 收起态第一行一旦超宽，`✕▢` 会被**整个挤到第二行**。所以那一行的宽度是**算出来的**（总宽 383 / 可用 406），改尺寸前先重算，别凭感觉调。同类坑：`margin` 也算进断行宽度。
- **★ 离屏实测要跑真逻辑、别写桩**（v2.1.0 的做法）：`main.js` 没法被测试 `require`（会把 app 启动一遍），所以把"纯计算/纯编排"抽成独立模块（`bg-protocol.js`、`win-mini.js`），测试直接 `require` 它、拿**真窗口**跑 —— 上面那个 `setResizable` 的坑就是这么抓到的，写桩测不出来。
- **`display: contents` 是"不改 HTML 结构就能拆分组"的利器**（v2.1.0）：mini 下让 `.np` / `.volume` 的盒子消失，子元素直接变成 `.player` 的 flex 项，于是封面和歌名能拆到两行去。
- **★ `before-quit` 设"正在退出"标记，比"手动设 forceQuit 标记"覆盖更全**（v2.2.0）：托盘「退出」/ `Ctrl+Q` / 系统关机 / 任务管理器结束 / 任何 `app.quit()` **全都**会先过 `before-quit`。窗口 `close` 里读 `app.quitting` 决定"真退还是拦下"。
  ⚠️ **但 Neko 和参考项目 biu 有关键差别**：biu 关窗前**不存盘**（实时 store），所以它的 `close` 里 `if (quitting) return;` 直接放行；**Neko 必须仍然走存盘握手 `requestMainWindowClose()`** —— 规则是"`before-quit` 标记跳过**询问**，不跳过**存盘**"。抄 biu 时别把这句一起抄过来。
- **★★ "读档补洞"绝不能写成白名单重建**（v2.2.0 修的真 bug，v2.1.0 埋下）：`const s = { theme, volume, bg, glass, autoLyric }` 这种"只列认识的字段"会让**所有新加的设置项存得进、读不出**（症状：改了设置下次打开又变回去）。正确写法是 `const s = Object.assign({}, old)` —— **从存档里已有的出发，只补不删**，不认识的新字段原样留着。已抽成 `src/store-migrate.js`，`verify.js` 加了两条哨兵守着。
- **★ 去重缓存只对"我这边驱动状态"成立**（v2.2.0）：界面把 `uiState` 报给主进程时做了去重（`lastUiStateKey` 一样就不发）。但**主进程自己也会改同一个状态**（勾了"设为默认值"时它自己改 `closeAction`）→ 之后界面算出的 key 正好撞上旧缓存，**这次上报被吞掉**。所以必须留一个 `forceReportUiState()` 出口（先 `lastUiStateKey = ''` 再上报），在"改了设置"处用它。
- **★ 状态上报的回调要放在"没变就跳过"的外面**（v2.2.0 修的真 bug）：`reportUiState()` 写在 `onWinMiniState` 的 `if (!changed) return` **里面**，进 mini 时界面已先改了本地状态、主进程回推的"没变"被跳过 → 第一次进 mini 的封面位置永远传不出去。
- **★ 抽独立模块让离线实测跑真逻辑**（v2.2.0 沿用并扩大）：`main.js` 没法被测试 `require`，所以把纯逻辑抽成**不 `require('electron')`** 的模块 —— 已有 `bg-protocol.js` / `win-mini.js`，v2.2.0 又加了 `app-menus.js`（托盘菜单 / 任务栏任务 / 关窗决策 / 命令行白名单）和 `store-migrate.js`。测试直接 `require` 它们。
- **★ 菜单怎么测**：`Menu.buildFromTemplate` 的模板里全是 `click` 回调，没法直接比对 —— 写一个 `describeMenu(tpl)` 把模板**压成纯数据**（`click` 只记"有没有函数"），再 `JSON.stringify` 逐项对比。菜单里所有动作都通过传入的 `handlers` 调用，模块本身零副作用。
- **★ 任务栏/托盘的几条 Windows 硬限制**（v2.2.0）：`setThumbarButtons` **只吃 `nativeImage`、不认 SVG**；**只要有一个图标是空的，整组按钮都不显示**；播放/暂停是**同一个按钮换图标**，状态一变就得**重设**；`setUserTasks`（任务栏右键「任务」）**不支持子菜单** —— 这就是"带层级的播放模式菜单一定挂托盘上"的原因；"缩略图换成封面"（网易云那种）走的是 Windows 私有 `DwmSetIconicThumbnail`，**Electron 没暴露**，只能用 `setThumbnailClip` 近似"裁窗口的一块"。
- **★ `coverRect` 由界面量好再交给主进程**（v2.2.0）：封面在界面的什么位置是**布局**的事，写死在主进程里改一次 CSS 就错一次。流程：界面 `getBoundingClientRect()` → 随 `uiState` 上报 → 主进程 `setThumbnailClip()`；退出 mini 报 `null` → 主进程 `setThumbnailClip({0,0,0,0})` 复位。
- **★★ 预览不能当验收**（v2.2.1 最痛的一条）：`make-icons.js` 里画图函数的形参写成了 `(size, x, y)`，而 `renderRGBA` 是按 `paint(x, y)` 调的 —— "x 坐标"被当成尺寸，写盘的 16 个图标全变成**纯色块**或**完全透明**。但**接触表 `icons-preview.png` 是正确的**，因为它走的是另一条（写对了的）代码路径。**两套代码 → 检查白做。**
  - 规矩：**凡是"只在最后一步才写盘"的产物，都要把写盘的东西读回来验一遍。** 已有 `.verify/check-icons.js`（解码 PNG 数像素：全透明 / 纯色块 / 着墨比例 / 最亮处不到 200 / 两个图标一模一样）。
  - 同类教训：手搓图形时，**线条要对齐像素中心**（5.5 而不是 5），否则 1.6 宽的线骑在像素边界上，每个像素最多覆盖 3/4，整枚图标比别的最淡一档。
- **★ `setThumbarButtons` 会静默失败，而且对时机敏感**（v2.2.1）：它**返回布尔值**表示成功，失败时**不报错**。窗口还没显示出来时（`show: false` 建的窗口，真正显示要等 `ready-to-show`）调用会返回 `false` 且什么都不做。规矩：**一定要看返回值**，并且**在 `show()` 之后**再设。
- **★ "用户点 ✕"只有一条入口是对的**（v2.2.1）：`ipcMain.on('win-close')` 曾直接调 `requestMainWindowClose()`，**绕过了 `mainWindow.on('close')` 里那套"询问 / 缩小到托盘 / 彻底退出"决策** —— 表现是"第一次点 ✕ 弹窗不出现、直接退干净"。正确写法是 `mainWindow.close()`，让 `close` 事件里的 `preventDefault()` + `decideCloseAction()` 接管；真要退时**由那个处理里**再回头调 `requestMainWindowClose()` 走存盘握手。
- **★ 小心"只在某条分支才写存档"的设计**（v2.2.1 修的真 bug）：v2.0.5 给合集加的 `DB.collectCovers` 只在"重新拉一遍曲目表"时才写，而 `collectEntriesFor()` 一旦命中本地缓存就**直接早退** → 已缓存的合集永远填不上（用户真机上 `collectParts` 有 32 个、`collectCovers` **0 条**）。规矩：**凡是"缓存命中就早退"的路径，都要问一句"那条路径上会不会漏掉什么要存的东西"**，必要时补一个异步的 `backfill*()` 自愈。
- **★ 注意"看起来不用查了"的早退**（v2.2.1）：合集里的曲目**自带 `cid`**，`ensureCid()` 一进来发现"cid 已经有了"就早退、**根本不去查 `videoInfo`** —— 于是封面永远拿不到。所以"补封面"必须在 `playAt()` 里**单独立一道**（`if (!track.cover) backfillCover(bvid)`），不能指望搭 `ensureCid` 的便车。
- **★ 数据经常是"后到的"，别只在开头贴一次**（v2.2.1）：封面要先查一次 `videoInfo` 才有，所以"贴封面"抽成了 `applyTrackCover(track)`，**什么时候拿到就什么时候贴**（开机恢复那一首也一样要异步补）。
- **★ `.ico` 是多分辨率容器**（v2.2.0）：6 字节文件头 + 每张 16 字节目录项 + 直接跟图片数据（Vista 后允许内嵌 PNG）；系统按 DPI 自己挑。`.verify/make-icons.js` 一次手搓 17 个图标（纯 Node，`zlib.deflateSync` + 手写 CRC32 + 4×4 子采样）。**托盘菜单小图标是深色的、缩略图按钮图标是白色的**（要压在深色预览底上），两套颜色别混用。
- **测试里音频 `src` 桩不能给空串**：Chromium 会 `new URL('')` 抛 `Invalid URL`，污染报告；给个合法 URL（如 `https://example.invalid/a.m4s`）即可。

**上一轮（v2.0.4）的主要成果** —— 修「播放失败：The play() request was interrupted by a new load request.」：`playAt()` 里有两段 `await`（补 `cid`、取音频地址），这期间用户完全可能又点了另一首 → **两个 `playAt` 叠在一起跑**，后一个换掉 `audio.src` 就把前一个还挂着的 `audio.play()` 打断（Chromium 的 `AbortError`）。旧代码把它**当"真失败"**：弹「播放失败」+ 900ms 后自动跳下一首 —— 你明明已经在听歌了。**它根本不是"取歌失败"**。改法：`playSeq` 序号 + 3 处"过期就放弃"闸门 + `isPlayInterrupted()` 静默 + 自动跳歌加序号闸门 + `safePlay()` 统一包住三处不 `await` 的 `audio.play()`。

**上一轮（v2.0.3）的主要成果** —— 修「最近播放里播放过的歌全都显示成正在播放」：分P 视频**每一集共用同一个 `bvid`**（靠 `cid` 区分），而 `rowIsPlaying` 里"只要 bvid 一样就算在播"那条兜底把**兄弟集数**也点亮了；现在加了闸门「这一行自己就是合集里的一集 → 不跟着亮」，并删掉一条反向误判（会误伤 UP 合集）。判据与两道闸门写在 `docs/技术说明.md` 第 9 节。
