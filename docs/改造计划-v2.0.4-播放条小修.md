## 一、逐条真凶（行号级）

### 1.1 播放条封面为什么是空的

**先看现在这段代码**（`src/ui/app.js:618`）：

```js
$('npCover').style.backgroundImage = track.cover ? `url("${track.cover}")` : 'none';
```

→ **只要这一首歌没有 `cover` 字段，就设成 `none`**，于是只剩 CSS 里的占位底色
`--track-bg: #26263a`（`style.css:17` / `style.css:692`）—— 就是你截图里那块灰紫色方块。

**那为什么这一首会没有 `cover`？**（关键，往下看）

翻代码发现一条**专门把封面剥掉**的路径（`src/ui/app.js:908-913`）：

```js
// 存一份剥掉封面 URL 的曲目表（封面是长链接，上百集全存会把存档撑大）
DB.collectParts[track.bvid] = entries.map((e) => ({
  bvid: e.bvid, cid: e.cid, page: e.page,
  title: e.title, duration: e.duration, author: e.author,
}));                                   // ← 这里没有 cover
```

而这个缓存会被**当成曲目表读回来**（`src/ui/app.js:897-899`）：

```js
async function collectEntriesFor(track) {
  const cached = DB.collectParts[track.bvid];
  if (cached && cached.length > 1) return cached;   // ← 直接返回，封面是空的
  ...
```

再往上（`src/ui/app.js:947` → `buildSequence()` 的 ② 段）：**播放时摊平合集用的就是这个表**。

**所以整条链是**：

```
你展开过一个合集（比如 134 集）
   ↓ 第一次：走网络，条目是带封面的（buildCollectionEntries 里有 cover）
   ↓ 同时：把这份表"剥掉封面"存进存档 DB.collectParts（为了不让存档变大）
关掉软件，再打开
   ↓ 再播这个合集 → 走缓存（collectEntriesFor 直接 return cached）
   ↓ 缓存里的条目没有 cover
播放条 → track.cover 是空的 → backgroundImage = 'none' → 只剩一块占位底色
```

**结论（诚实版）**：这条路径**确定**会让封面消失，而且**列表里的封面也会一起消失**（同一个数据源）。
我不能 100% 确认你截图那首「花期 - 皓晨音乐」就是从这条路径来的（我没有你的存档），
但**判断依据**是：如果你那首是**从合集/选集里播的**，而且这个合集**之前展开过**（重启过软件），那 100% 就是它。
如果不是，我再另找（下面 §1.1 的"顺手加的兜底"也能覆盖住网络失败那种情况）。

### 1.2 「收起」为什么不自动隐藏

`src/ui/style.css:712-714`：

```css
/* 歌词页正开着：封面上常驻一句"收起" —— 再点一下就返回原来的窗口，
   不用猜它是不是个开关。（和"词"按钮一样，点了就有反馈。） */
.np-cover.open::after { content: "收起"; opacity: 1; }
```

**这不是 bug，是当初"故意"做的** —— 想让你一眼看出"再点一下就能收起"。
但它**常驻**了：只要歌词页开着，那块就一直盖着「收起」，挡住了封面，看着像没做完。

对比一下：没开歌词页时，那句「歌词」是**鼠标移上去才出现**的（`style.css:710` `.np-cover:hover::after { opacity: 1; }`）。

→ **你要的是和它一致：移上去才出现。**

## 二、打算怎么改

### 2.1 「收起」改成"移上去才出现"（1 行）

`src/ui/style.css:714`：

```css
/* 改前 */
.np-cover.open::after { content: "收起"; opacity: 1; }
/* 改后：把常驻的 opacity:1 去掉 —— 只换文字，出现时机交给上面那条 :hover 规则 */
.np-cover.open::after { content: "收起"; }
```

改完的效果：歌词页开着时，封面**干净**；鼠标移上去才浮出「收起」。
（`style.css:712-713` 那段注释也要一起改，不然注释和代码对不上了。）

### 2.2 播放条封面：让缓存里也有封面

**核心思路**：给每个合集**只存一张封面**（不是每集都存），读回来时套给每一集。

- 存档只多 **1 个 URL / 合集**（而不是 134 个）—— 尊重原作者"别把存档撑大"的顾虑。
- 改动点：
  - `src/ui/app.js:908-913` 存缓存时，顺手把这次查到的 `info.cover` 记下来（比如 `DB.collectCovers[bvid] = info.cover`）。
  - `src/ui/app.js:897-899` 读缓存时，把这张封面**套给每一条**（`e.cover || coverOf(bvid)`）。
  - `src/ui/app.js:3526` 那个"补洞"的地方，一起加上 `DB.collectCovers`（缺省 `{}`，老存档零迁移）。

**取舍（先说清楚）**：UP 合集（season）里**每一集原本可能各有各的封面**，这么做之后会**统一成合集封面**。
我认为可以接受（同一个合集用一张封面反而更整齐）；你要是想"每集保留自己的封面"，那就得逐集存，
134 集大约多 10KB 存档 —— 你说了算（§5 Q2）。

### 2.3 顺手加个"没封面"的兜底

不管上面那条修得对不对，**网络失败 / 老数据**都可能让封面是空的。现在空着就是一块纯色，像坏了。

改法：给 `.np-cover` 加一条规则 —— 没有封面时（用 `.no-art` 类标记）显示一个**淡淡的音符图形**居中，
而不是一块什么都没有的色块。

- 纯 CSS（背景放一个内联 SVG data-URI，`img-src` 里已经放行了 `data:`，见 `index.html:6`）。
- `app.js:618` 那里顺手 `classList.toggle('no-art', !track.cover)`。

> 这一条**不改数据、只改观感**，就算 §2.2 的修法以后又出别的问题，界面也不会看起来像坏了。
