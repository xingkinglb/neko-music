# 改造计划：启动默认进「发现」+ 去掉侧栏「搜索」入口 + 视频背景

> 本轮三件事：① 启动默认打开「发现」而不是「搜索」；② 侧栏那个「搜索」入口删掉；
> ③ 新增「视频背景」（用视频当壁纸）。
> 前两件是同一个根（导航模型），第三件是新功能、体量最大。
> 这份是**动手前的施工图**，逐条对账到代码行号 + 方案 + 验证判据，确认后再改代码。

## 〇、先说结论：改完以后是什么样

| 你现在看到 | 改完以后 |
|---|---|
| 打开软件，停在「搜索」页，只有一句"输入关键词去 B 站找歌吧" | 打开软件直接进**「发现」**，一上来就有 12 首随机推荐 |
| 侧栏第二个是「搜索」，点进去是空占位页 | 侧栏**没有「搜索」这一项**了（发现 / 我喜欢 / 最近播放 / 我的歌单） |
| —— | 顶部搜索栏**照旧能搜**，回车就出结果页（搜索功能一点没少，只是不再占侧栏位置） |
| 背景只能是图片 | 背景可以选**一段视频**当壁纸（默认静音、循环播放），图片/视频随时切换 |

**一句话澄清**（避免误会）：所谓"删掉搜索界面"，实际删的**只是侧栏那一个入口**。
搜索功能本身、以及"搜索结果页"必须保留 —— 顶部搜索栏回车后，结果就是渲染在那一页上的。
侧栏那个入口点进去只有一句占位提示，从来没被真正用到，删掉它没有副作用。

## 二、改造方案

### P1 启动默认进「发现」（小改动）

- `app.js:109`：`let currentView = 'search';` → `'discovery'`。
- `index.html:229`：给「发现」项加 `class="nav-item active"`；删掉「搜索」项的 `active`（该项随 P2 一起删）。
- 效果：`boot()`（`app.js:3006`）末尾 `renderAll()`（`3040`）会走 `discovery` 分支，自动 `loadDiscovery()` 拉推荐（`app.js:1439-1442`）。

### P2 去掉侧栏「搜索」入口（小改动，但牵动几处）

- `index.html:232-234`：删掉整个 `<div class="nav-item" data-view="search">…搜索…</div>`。
- `app.js:1436-1447` 的 `renderAll()` **保留** `if (currentView === 'search') renderSearch();` —— 顶部搜索栏还要用它渲染结果页。
- 新增 `syncNavHighlight()`：在 `renderAll()` 开头按 `currentView` 统一刷侧栏高亮（替掉现在"只在点击时改"的写法）。
  - `currentView` 是 `discovery/favorites/history/playlist:xxx` 时，点亮对应项；
  - 是 `search`（顶部搜索出来的临时结果页）、`up`、`parsed` 时，**四项都不点亮**（它们不属于任何侧栏分类，这样反而更准）。
- 三处"回退到搜索页"统一改成**回退到「发现」**：
  - `app.js:1046`：`currentView = 'search'; renderSearch();` → `currentView = 'discovery'; renderAll();`
  - `app.js:1931-1932`：详情页没有来路时同上；
  - `app.js:1942`：UP 页「← 返回」同上（回首页比回一个空搜索页合理）。
- 文案：`app.js:1264` `'← 返回搜索'` → `'← 返回发现'`。

### P3 视频背景（大改动，分三小块）

#### P3.1 主进程（`main.js`）—— 让 `bg://` 能"边读边传"视频

- **`bg://` 改流式 + 支持 Range**（`main.js:137-166`）：
  - 现在：`fs.readFileSync` 读完整份再返回（`155-160`）。视频几十上百 MB，不能这么干。
  - 改成：解析请求头里的 `Range` → `fs.createReadStream(file, {start, end})` → 转成 `ReadableStream` 返回；
    返回 `206 Partial Content` + `Content-Range: bytes a-b/total` + `Accept-Ranges: bytes`；
    没带 Range 时返回 `200` + 完整流。
  - 这两道安全闸（文件名白名单 `143`、路径越界检查 `148`）原样保留，**视频和图片共用**。
- **`BG_MIME` 加视频类型**（`main.js:53-56`）：`.mp4: video/mp4`、`.webm: video/webm`、`.mov: video/quicktime`。
- **`bg:pick` 支持选视频**（`main.js:466-486`）：
  - 拆成按类型选：`bg:pick`（图片，扩展名同现在）+ 新增 `bg:pickVideo`（视频）；
  - 视频加**大小上限**（建议 ≤ 200MB，超了返回 `{error:'视频太大了…'}`，避免卡爆）；
  - 复用现有逻辑：复制进 `%APPDATA%\neko-music\backgrounds\`，`clearBgDir()` 一次只留一份。
  - 注意：图片和视频**共用** `backgrounds/` 目录、共用"一次只留一个"策略（换背景时旧的会被清掉）。

#### P3.2 渲染层（`index.html` / `app.js` / `style.css`）—— 把视频铺成壁纸

- **CSP 放行**（`index.html:6`）：`media-src 'self' bili:` → `media-src 'self' bili: bg:`。
- **背景层加一个 video**：`#bgLayer`（`index.html:203`）里放
  `<video id="bgVideo" muted loop playsinline></video>`，CSS 让它 `object-fit:cover`、铺满、`pointer-events:none`、默认 `display:none`。
- **`applyAppearance()` 加视频分支**（`app.js:202-228`）：
  - `s.bg.kind === 'video' && s.bg.file` → 显示 video、`src = bg://local/<file>`、`play()`；
  - 否则 → 隐藏 video、`pause()`（不播的视频要停掉，省电）；
  - 压暗（`--bg-dim`）和模糊（`--bg-blur`）**对视频同样生效**（复用 `.bg-layer::after/::before` 与 filter）。
- **设置面板**（`index.html:467-474`）：「背景」区从"选择图片 / 清除背景"扩成
  「选择图片 / 选择视频 / 清除背景」，下面加视频专属开关：
  - **静音**（默认**开**，建议锁死不可关，否则会跟音乐打架）；
  - **循环**（默认开）；
  - **播放速度**（0.5× / 1× / 1.5× / 2×，可选，默认 1×）。
- **省电**（建议做）：窗口失焦或最小化时自动 `pause()`，恢复时 `play()`。

#### P3.3 数据与兼容

- `DB.settings.bg` 从 `{file, dim, blur}`（`app.js:1739`）扩成
  `{file, kind:'image'|'video', dim, blur, video:{muted:true, loop:true, speed:1}}`。
- **老存档零迁移**：没有 `kind` → 默认 `'image'`（= 旧行为，完全一样）；没有 `video` 子项 → 补默认值（跟现有 `migrateSettings()` 放一起）。
- 存档仍在 `%APPDATA%\neko-music\`，**不进 Git**（隐私边界不变）。

## 五、已知取舍（说在前面，免得改完你觉得怪）

1. **视频背景吃显存和电**：所以默认**静音 + 循环**，并建议做"失焦/最小化自动暂停"。
2. **只支持 mp4 / webm / mov**：这三种 Chromium 内核能稳解；AVI / MKV 等容器不保证能播，选了会提示。
3. **视频有大小上限**（建议 200MB）：太大的视频一次性加载会卡，超过就提示换小的。
4. **图片和视频共用一个背景目录**：换背景时旧的会被清掉（沿用现在"一次只留一份"的策略），所以不能同时留一套图 + 一套视频。
5. **删的只是侧栏入口**：搜索功能、搜索结果页、顶部搜索栏全部保留，一点没少。
6. **搜索结果页侧栏不点亮**：因为它是"临时页"，不属于发现/我喜欢/最近播放任何一个分类；这样比硬点一个更准。
