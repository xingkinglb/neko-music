## 问题 ① mini 模式不置顶，随便一个窗口都能盖住它

**你说的话**：「这个 mini 模式应该跟歌词一样置顶在屏幕上吧，现在是随便一个窗口都能覆盖」

### 现状（对账到行号）

| 谁 | 置顶了没 | 在哪 |
|---|---|---|
| 桌面歌词小窗 | ✅ 置顶，而且用的是**最高一级** | `src/main.js:1086` `alwaysOnTop: true`，`src/main.js:1100` `setAlwaysOnTop(true, 'screen-saver')` |
| 主窗口（mini 就是它） | ❌ 完全没设 | `src/main.js:309-352` 的 `winOpts` 里没有 `alwaysOnTop`；`applyMini()`（`src/main.js:562`）只改窗口尺寸 |

`screen-saver` 是 Electron 里置顶的"最高档"，比普通置顶还高一层，连全屏程序都盖得住 —— 桌面歌词用的就是它。

### 方案

1. **在 `pushMiniState()`（`src/main.js:570`）里加置顶开关**：
   mini 开着 → `mainWindow.setAlwaysOnTop(true, 'screen-saver')`；退出 mini → `setAlwaysOnTop(false)`。
   放这里的理由：**两个入口都会经过它** —— 界面发 `win:mini`（`main.js:850`）和托盘 / 任务栏点「mini 模式」（`main.js:554` → `applyMini()` → `pushMiniState()`）。放一处，两条路都盖到。
2. **启动时如果存档就是 mini**（`main.js:303-307` 读 `settings.window.mini`）：`winOpts.alwaysOnTop = startMini`，并在 `ready-to-show` 里再补一次 `setAlwaysOnTop(true, 'screen-saver')`（和 v2.2.1 修 `setThumbarButtons` 的时机问题同一个道理 —— 窗口没显示出来时设了可能不算数）。
3. **完整模式不置顶**，维持现状。

### 验证判据（离屏实测，不写文字断言）

- 进 mini 后 `mainWindow.isAlwaysOnTop() === true`；退出后 `=== false`。
- 存档是 mini 时启动 → 开窗即置顶。
- 静态自检加一条：`main.js` 里 mini 分支必须出现 `setAlwaysOnTop`（防止以后被改掉）。

### ✅ 已拍板：用最高档 `screen-saver`

（Neo 2026-10-14 选定）跟桌面歌词同档 —— 谁都盖不住它。
代价知情：**全屏视频 / 全屏游戏时它也会浮在画面上**。将来若觉得挡事，再按"设置项"方案加开关。

## 问题 ② 歌名太长时，mini 右边那排图标被挤出窗口

**你说的话**：「不知道什么情况下（我猜测是歌曲名称过长），mini 模式的图片会向后移动，且移出了 UI 界面」

### 根因（已实测确认，不是猜的）

我写了一个一次性探针（`.tmp/probe-mini.js`，不进仓库），在离屏真窗口里进 mini，用不同长度的歌名把每个元素的真实坐标量出来：

| 歌名长度 | 播放条（`.player`）实际宽度 | 右边那排图标 |
|---|---|---|
| 6 字 | **420**（正常） | ✕▢ 右边缘 = 420，正好贴边 ✅ |
| 27 字 | **420**（正常） | ✕▢ 右边缘 = 420 ✅ |
| 50 字 | **684** ❌ | ♡ 在 x=495、✕▢ 右边缘 = 684 → **越界 264px** |
| 100 字 | **992** ❌ | ✕▢ 右边缘 = 992 → **越界 572px** |

**窗口只有 420 宽，但播放条被撑到了 684 / 992** —— 于是右边那排图标全被推到窗口外面去了。这就是你看到的"图标往后移、移出界面"。歌名不长的时候（≤ 约 384px）不会触发，所以你只在某些歌上碰到。

**为什么会撑宽？一条链，四个环**：

1. `body.mini .np { display: contents }`（`src/ui/style.css:1597-1598`）—— 这是 v2.1.0 的招：让 `.np` 这个"分组盒"消失，封面 / 歌名 / ♡ 直接变成播放条的子元素，不用改 HTML 就能重排。
   **但盒子一消失，它身上的约束也跟着消失了** —— `.np { min-width: 0 }`（`style.css:688`）本来在拦着"不许被内容撑宽"，现在没人拦了。
2. `.np-title` 有 `white-space: nowrap`（`style.css:729`）—— 意味着这首歌名的**"最小宽度"= 整首歌名的完整宽度**（50 字约 625px）。它自己不会缩。
3. `.np-meta` 成了播放条的直接子元素，它写着 `flex: 0 0 100%`（`style.css:1609`）。这里的 `100%` 指"父容器内容宽"。而播放条 `.player` 是 `.app` 网格里的一格，**网格项默认 `min-width: auto`**（= 不许比内容的最小宽度更窄）→ 播放条被内容撑到 684。
4. 播放条一宽，`flex-basis: 100%` 就跟着变成 670 → 整行都按 684 排 → ♡🔊☰✕▢ 全部跑到窗口外。

> 一句话：**`display: contents` 把 `.np` 的"防撑宽"一起吃了，而播放条自己没设 `min-width: 0`。**
> 完整模式为什么没事？因为完整模式下 `.np` 的盒子还在，`min-width: 0` 还在干活。

### 方案（实测有效的三行）

在 `src/ui/style.css` 的 mini 一节里加：

```css
body.mini .player   { min-width: 0; }                                    /* ★ 关键：让播放条可以被窗口"卡住" */
body.mini .np-title { flex: 1 1 auto; min-width: 0; }                    /* 标题先让位，超长出省略号 */
body.mini .np-sub   { flex: 0 0 auto; min-width: 0; max-width: 45%; }    /* 作者名保住，最多占 45% */
```

**我两种改法都实测过**：

| 改法 | 结果 |
|---|---|
| 只加 `min-width: 0` | 不再越界 ✅，但**超长歌名会把作者名挤没**（作者只剩 6~14px，等于看不见） |
| 上面三行 | 不再越界 ✅，且作者名保住（短作者原样显示、长作者最多占 45%）→ **采用这个** |

改完五种长度的实测结果（都在窗口内）：

| 歌名 | 播放条宽 | 标题宽 | 作者宽 |
|---|---|---|---|
| 6 字 | 420 | 345 | 39 |
| 27 字 | 420 | 338 | 46 |
| 50 字 | 420 | 361 | 23 |
| 43 字 + 长作者 | 420 | 253 | 131 |
| 100 字 | 420 | 368 | 16 |

### 验证判据

- 新写 `test-round13.js`：进 mini，用上面 5 种长度各量一遍，断言
  ① 播放条宽 == 420（视口宽）；② **每个元素的右边缘 ≤ 420**（这是这次的哨兵）；③ 播放条 `scrollWidth == clientWidth`（没有横向溢出）；④ 标题 / 作者都还在同一行（y 相同）。
- 这一条**在修复前的代码上会真的失败**（会量出 684）—— 符合项目"测试要有判别力"的规矩。

## 问题 ③ 合集面板的「加入队列」多余，把搜索框挤成一个字

**你说的话**：「展开合集后这个列表里的【加入队列】是不是不需要了，因为点击播放时会自动加入队列，而且现在这样导致搜索框过窄只能显示一个字」

### 现状（对账到行号）

- 按钮在 `src/ui/index.html:438`；文案由 `src/ui/app.js:1366-1367` 每次刷新时更新。
- 点它走 `queueCollection()`（`src/ui/app.js:1398-1418`），监听绑在 `src/ui/app.js:1457`。
- 面板固定宽 400px（`style.css` 的 `.collect-panel`），一行要塞 4 个东西：

| 元素 | 估算宽 |
|---|---|
| 「全部禁用」 | ~76 |
| 「播放全部 (134)」 | ~110 |
| 「加入队列 (134)」 | ~110 |
| 3 个 8px 间隔 | 24 |
| **合计** | **~320** |

400 − 32（左右内边距）= 368 可用 → **搜索框只剩 ~48px**，正好只够显示一个字。和你截图完全一致。

### 为什么它确实多余

- 点列表里**任意一行** → `playCollectEntry()`（`app.js:1387-1396`）→ `playTracks(...)`：把"启用的那几集"整体设成队列并开始播。
- 「播放全部」→ 同一件事（`app.js:1449-1456`）。
- 所以队列**一定会被建好**，`加入队列` 在常规用法下是重复入口。

### 方案

- 删 `index.html:438` 那行按钮。
- `app.js` 删三处：`queueCollection()` 函数（1398-1418）、它的监听（1457）、`syncCollectBar()` 里的 `addQ` 两行（1366-1367）。
- `style.css:1504` `.collect-search` 加 `min-width: 140px`（以后按钮再多也不会把它挤没）。
- 结果：搜索框从 ~48px → **~166px**（能显示十几个字）。

### ✅ 已拍板：直接删掉按钮

（Neo 2026-10-14 选定）代价知情：以前那个「把整段合集**追加**到当前队列、**不打断**正在播的歌」的能力会失去 —— 之后队列只能靠"点某一行 / 点播放全部"重建（会从第一首开始播）。

### 验证判据

- 离屏实测：`#btnQueueCollect` 不在 DOM 里；`#collectSearch` 的实测宽度 ≥ 150；点某一行后队列长度 == 启用的集数。
- 静态自检第 27 类：把 `btnQueueCollect` 从"必需元素"里拿掉，**改成断言它不存在**（防回潮），并断言 `.collect-search` 有 `min-width`。
- `test-collect.js` 第 3 组「加入队列」改成「点行即建队列」。
