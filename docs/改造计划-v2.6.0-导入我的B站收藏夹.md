## 一、一句话说清这个功能

在侧栏「我的歌单」那一行、＋ 按钮的**左边**加一个按钮。点它进一个整页：

**认出你是谁 → 选来源（我的投稿 / 我的收藏夹）→ 挑视频（可跨收藏夹累积选）→ 起个名字 → 变成一个歌单。**

关键点（Neo 补充的）：**选择是跨收藏夹累积的** —— 在收藏夹 A 里挑 3 个，回到列表，进收藏夹 B 再挑 2 个，最后一起导入成**一个**歌单。

## 三、★ 核心设计：跨收藏夹累积的选择集

这是这一版最容易做错的地方，单独说清楚。

```js
// 独立于"当前在看哪一页"，所以翻页、换收藏夹、回列表都不丢
impState.selected = new Map();   // bvid -> { track, from }   from = 收藏夹 id 或 'up'
```

三条铁律：

1. **`selected` 只在两件事上被清空**：导入成功之后、用户点「清空选择」。**切换页面 / 翻页 / 换收藏夹一律不动它。**
2. 进任何一个收藏夹时，行的勾选状态**从 `selected` 反查**（`selected.has(track.bvid)`）——
   所以两个收藏夹里有同一个视频时，第二次进去它已经是勾上的，**不会重复计数**。
3. `from` 用来算收藏夹卡片上的「已选 N」角标：数 `selected` 里 `from === 该收藏夹 id` 的条数。
   已经全选的那个收藏夹，按钮文案变成「取消整个收藏夹」。

> 为什么用 `Map` 而不是数组：B 站收藏夹里同一个视频可能出现在多个收藏夹，用 `bvid` 当键天然去重。

## 四、技术实现（逐条对账）

### 4.1 后端 `src/bilibili.js`

| 改动 | 位置 | 说明 |
|---|---|---|
| 新增 `getMyInfo()` | 第 6 部分之前（挨着 `getFavFolders` 放） | `GET https://api.bilibili.com/x/space/myinfo`，认证方式就是 SESSDATA；返回 `{ mid, name, face }` |
| 没填 Cookie 时提前退出 | `getMyInfo()` 开头 | 照 `hasLoginCookie()`（`bilibili.js:533`）的写法，抛 `reason: 'no-cookie'`，**不去白跑一次请求**（和字幕那条一样的规矩） |
| 错误码带出来 | `requestJSON`（`bilibili.js` 第 3 部分） | 加一行 `e.code = json.code`。现在错误消息里虽然含 `-101`，但界面要字符串匹配才能识别，太脆。加了之后 `getMyInfo()` 能把 `-101` 映射成 `reason: 'cookie-expired'`，界面就能说「Cookie 可能过期了，重新填一次」 |
| `getFavMedias` 补总数 | `bilibili.js:455-470` | 加 `total: (json.data.info && json.data.info.media_count) || 0`（取不到就退化成 0，界面按 `hasMore` 兜底） |
| 导出 `getMyInfo` | `bilibili.js` 末尾 `module.exports` | 加一项 |

## 五、边界与失败提示（都要有，不能白屏）

| 情况 | 界面表现 |
|---|---|
| 没填 Cookie | 页面上直接给引导：「这个功能要用你自己的 B 站账号。去左下角『设置 → B 站』填一下 Cookie，再回来点这个按钮。」（**不发请求**） |
| Cookie 过期 / 失效（`-101`） | 「Cookie 好像过期了，去『设置 → B 站』重新粘一次」 |
| 被风控（`-352` / HTML 风控页） | 复用 `requestJSON` 现有的重试 + 提示文案 |
| 没有收藏夹 | 「你的 B 站账号下没有公开的收藏夹」 |
| 收藏夹是空的 | 「这个收藏夹里没有视频」 |
| 私密收藏夹 | **正常显示**（本人登录可见），卡片上带一个「私密」小标 |
| 已选 0 个 | 「导入选中的 N 个」置灰不可点 |
| 导入时有重复 bvid | 自动去重（`Map` 天然去重），最后 toast 里说明实际导入了几首 |
| 收藏夹超过一页 | 分页条（一页 30） |
