## 二、需求原文与三处设计确认

Neo 的需求：

```
【本地歌曲】界面是否可以在左侧设计一个展示文件夹的列表目录，
-全部歌曲
--本地下载（下载文件夹的位置）
--添加的文件夹1  x（x 是删除该文件夹索引）
--添加的文件夹2  x
且在【本地歌曲】界面右侧加上【批量选择】的按钮，供用户进行批量操作
（清空 / 全选 / 加入到文件夹）
```

三处拿不准的地方，用选择卡确认（**三项都选了推荐项**）：

| 决策点 | 选项 | 结论 |
|---|---|---|
| 左栏放哪 | 全局侧栏 / **界面内容区左侧栏** | **界面内容区左侧栏**（只属于本地歌曲页，不影响别的页面） |
| 怎么分组 | 按文件夹逐级 / **按「来源类型」** | **按来源类型**：本地下载 / 每个手动添加的文件夹 / 导入的歌曲 |
| 批量能做什么 | 移出库 / 加入歌单 / 收藏 | **三个都要**（工具条：全选 · 清空选择 · 收藏 · 加入歌单 · 移出库） |

## 三、做了什么（按用户能看到的分点）

### 3.1 左栏：文件夹列表

- 进「本地歌曲」页后，内容区变成**左右两栏**：
  - **左栏**：一行一个分组，带该组歌曲数。
    - `全部歌曲`（永远是第一行，含所有本地歌）
    - `本地下载`（`folderRoot` 是下载目录的那些）
    - `导入的歌曲`（一首首手动导入、不属于任何文件夹的）
    - `每个手动添加的文件夹`（名字取路径最后一段；悬停才出现 ✕）
  - **右栏**：当前分组筛选后的歌曲列表 + 头部的「批量选择」按钮。
- 点左栏任一行 → 右栏只显示那一组。
- 点文件夹行的 **✕** → **只删这一组的索引**（把这一组的歌从库里移出去），别的组不受影响。
- 删掉的正好是**当前正在看的那一组** → 自动退回「全部歌曲」（否则会停在一个空气分组上，右栏空白）。

### 3.2 右栏：「批量选择」工具条

- 头部有「批量选择」按钮；点一下进入勾选态。
- 勾选态下：
  - 每行左侧出现勾选框；点**整行 = 勾选**（不再是播放）。
  - 出现工具条：`已选 N 首` · `全选` · `清空选择` · `收藏` · `加入歌单` · `移出库`。
  - **全选只勾当前分组**（不跨组，避免误伤）。
  - 三个动作：一起收藏 / 一起加进某个歌单 / 一起移出库。
- **换分组、离开本页** → 自动退出勾选态（选择集是按当前分组挑的，留着会串到别的组）。

### 3.3 一条红线（沿用非破坏性）

「移出库」「删文件夹 ✕」**只删应用里的记录，绝不碰你磁盘上的文件**。
两处都有**反向断言**盯着（不许出现 `unlink` / `rmdir` / `copyFile`）。

## 四、关键技术判断（为什么这么做）

1. **分组信息必须来自「用户当时选的那个目录」，不准从每首歌的路径反推。**
   路径反推在两个场景会分错组：① 文件夹里还有子目录（每首歌路径层级不同，反推会碎成好几组）；
   ② 同名文件夹（`D:\音乐\A` 和 `E:\音乐\A` 最后一段都是 `A`，会并成一组）。
   所以 `local:pickFolder` 从本轮起返回 `{ root, paths, truncated }`，**`root` 是分组归属的唯一来源**，
   界面只用它。导入文件夹时把 `folderRoot = root` 写进每条记录。
   （判据：`folderRoot` 一律来自主进程，界面源码里不许出现"从路径反推"的写法。）

2. **老存档迁移只补不删。**
   `store-migrate.js` 给缺 `folderRoot` 的老条目补 `null`、缺 `src` 的补 `'file'` —— **原地 `forEach` 补，不用 `filter` 替换整个 `d.local`**。
   用 `filter` 替换会顺手吞掉格式异常但内容完好的条目（丢数据）。这条已被 `verify.js` 第 59 类与 `discriminate-56` 双向盯住。

3. **勾选要按「本地歌的身份」勾，不是按 bvid。**
   本地歌没有 bvid，拿 bvid 去查勾选集永远查不到。于是给 `trackRow` 抽出一个 `opts.pickKey`
   （默认 `'bvid'`；本地歌传 `'localPath'`）。下载勾选 / 导入勾选仍走 bvid，完全不受影响 ——
   这是本轮最核心的一处抽象。**`sameTrack` 的"本地歌按路径判等"分支必须排在 bvid 比较之前**（老规矩）。

4. **左栏行里的 ✕ 必须排在「点整行 = 切换分组」之前判。**
   ✕ 是行内元素，不先拦的话点击会被整行处理器吃掉，变成"点 ✕ 却切了组"。`verify.js` 有专门断言盯这个**判定顺序**。

## 六、测试基建的一次加固（写给下一个会话）

- `test-round21.js` 加了 `process.on('uncaughtException'/'unhandledRejection')` 兜底。
  本轮踩到「测试脚本自己抛异常 → Electron 静静挂着、报告停在半截」这个坑（外层只看得到 `timeout` 124，
  像"应用挂了"其实是"测试挂了"）。加了之后会立刻写报告并 `exit(3)`。
- 被**产品行为**反过来咬了一口：本轮新加的「换分组会自动退出勾选态」是对的，
  但测试里 `clickFolder('all')` 之后忘了重新进勾选态 → `s1.pick` 是 `null` → 读 `null.n` 把整轮挂住。
  **教训：测一个会"自动退出"的行为时，切换动作之后要显式重新进入那个状态。**
- `verify.js` 两条旧断言因本轮改动误报，已语义化：
  `pickSet.has(track.bvid)` → `(pickSet|selected).has(track.bvid|pickId)`；
  `currentTracks` 的 local 分支放宽成 `(localFilteredTracks|localTracks)`（"必须走 Filtered"由第 59 类管）。
- 新断言自己踩的坑：`appjs` 是**去注释**过的，拿注释文字当 `indexOf` 锚点恒为 -1
  → 改用唯一代码语句（`lastIndexOf('startFromView(tracks, i)')`）。
