# 改造计划 v2.5.0 —— UP 主页改成「先取总数 + 分页」

> 状态：**待 Neo 批准**
> 来源：Neo 2026-10-14 真机反馈（配现状图 + 目标样式图）
> 版本规则：新行为（交互方式换掉）→ 中间位 +1 取 **v2.5.0**

**你说的话**：「目前进入作者主页是默认加载30条，想要更多需要点击右上角的【加载更多】，这操作体验很不好，能否设计成如图这样，先获取总共有多少，然后再按每页30划分」

---

## 一、现状（对账到行号）

### 后端其实**已经知道总数了**，只是没往外传

`src/bilibili.js:482-506` 的 `getUpVideos(mid, pn)`：

```js
const page = (json.data && json.data.page) || {};        // ← B 站返回的对象里就带总数
return {
  list: vlist.map(...),
  hasMore: pn * 30 < (page.count || 0),                  // 第 504 行：拿它算了"还有没有下一页"
};
```

第 504 行已经在用 `page.count`（B 站给的总投稿数），但**没把它返回给界面** —— 界面拿不到总数，就只做得出"还有/没有下一页"，做不出"第 x / 共 y 页"。

### 界面是"累加"模式，不是"翻页"模式

| 位置 | 现在的写法 | 问题 |
|---|---|---|
| `src/ui/app.js:1899` | `let upState = { mid, name, list, page, hasMore, loading, error }` | 没有 `total` |
| `src/ui/app.js:1914-1936` | `upState.list = pn === 1 ? mapped : upState.list.concat(mapped)` | **累加**：翻到第 5 页时列表里堆着 150 条 |
| `src/ui/app.js:1947` | 副标题「已加载 N 个视频（还能继续往下加载）」 | 说的是"已加载多少"而不是"总共有多少" |
| `src/ui/app.js:1951` | 右上角「加载更多」按钮 | 要一页一页点 |
| `src/ui/app.js:3301` | `if (id === 'btnMoreUp') loadUp(upState.page + 1)` | 点了就往后再拉 30 条、追加到列表末尾 |

## 二、方案（4 步）

### 第 1 步：后端把总数带出来（1 行）

`src/bilibili.js:492-505` 的返回对象里加一项：

```js
return {
  list: vlist.map(...),
  total: page.count || 0,     // ★ 新增：B 站给的总投稿数
  hasMore: pn * 30 < (page.count || 0),
};
```

`hasMore` **保留**（别的地方可能在用，删了容易踩坑）。

### 第 2 步：界面从"累加"改成"翻页"

- `upState` 加 `total`。
- `loadUp(pn)`（`app.js:1914-1936`）里：

```js
upState.list  = mapped;                       // ★ 只装这一页（原来是 concat 累加）
upState.page  = pn;
upState.total = res.total || mapped.length;
```

> 注意：翻页时列表是**替换**，所以"正在播放"的高亮、滚动位置这些跟着重算 —— 和第 3.9 部分现有逻辑一致，不用额外处理。

### 第 3 步：分页条（照你给的那张图）

新增一个 `paginationHTML(page, totalPages)`，产出：

```
[上一页] [1] [2] [3] [4] [5] [6] [7] … [28] [下一页]
```

规则：
- **当前页高亮**（用主题色 `--accent`，和界面其它地方统一）
- 页码多的时候中间用 `…` 省略：**首页 + 当前页前后各 2 页 + 末页**（例：在第 1 页显示 `1 2 3 … 28`；在第 5 页显示 `1 … 3 4 [5] 6 7 … 28`）
- 首页时「上一页」置灰不可点；末页时「下一页」置灰不可点
- 挂在**列表下方**（居中一条），顶部副标题改成「**共 N 个视频 · 第 x / y 页**」

点击处理挂到现有的按钮代理里（`app.js:3294-3309` 那一段 `if (id === ...)`），和搜索页的上一页/下一页同一个套路。

### 第 4 步：右上角按钮改成「播放本页 (30)」（✅ 已拍板）

分页之后"全部"指哪一批？**已定：改名成「播放本页 (30)」，只播当前这一页。**

- 理由：一页 30 首正好是一个好用的队列；要是播 800 首，队列抽屉、随机播放、单曲循环都会变得很难用（而且每首都要先补 cid 才能播，会连着发 800 次请求）。
- 位置：右上角原来「加载更多」那个位置空出来了，正好放它。
- 实现：`app.js:3300` 的 `btnPlayUp` 改成 `startFromView(upState.list, 0)`（本来就是播 `upState.list`，翻页后它自动就是"当前页"），文案在 `app.js:1950` 改。
- 以后若真想要"整个空间的全部视频"，再加一个按钮就行（单独一轮）。

## 三、验证判据（离屏实测，不写文字断言）

新写 `.verify/test-round14.js`（或并进 `test-ui.js`），桩数据给 `total = 137`、每页 30：

| 验什么 | 判据 |
|---|---|
| 页数算得对 | 137 / 30 向上取整 = **5 页** |
| 页码条内容 | 第 1 页显示 `1 2 3 4 5`（无省略号）；构造 `total = 837`（28 页）时，第 1 页显示 `1 2 3 … 28` |
| 点第 2 页 | 桩里收到 `pn === 2`；列表**替换**成第 2 页的 30 条（**不是 60 条**） |
| 边界置灰 | 第 1 页「上一页」不可点；最后一页「下一页」不可点 |
| 旧按钮没了 | 列表里**不存在** `#btnMoreUp` |
| 总数显示 | 副标题里出现「共 137 个视频」和「第 1 / 5 页」 |

**判别力**：这一组在改造前的代码上会真的失败（现在没有 `total`、没有分页条、列表是累加的）—— 符合项目"测试要有判别力"的规矩。

静态自检加两条：
- `src/bilibili.js` 里必须出现 `total: page.count`
- `src/ui/app.js` 里必须有 `paginationHTML`，且**不再有** `btnMoreUp`

回归：`test-ui.js`（它现在会点作者名验 UP 主页，桩数据要补 `total` 字段）。
