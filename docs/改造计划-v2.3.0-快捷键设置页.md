然后在 `.pane[data-pane="bilibili"]`（`index.html:680`）**后面**加一整块：

```html
<!-- ========== 快捷键 ========== -->
<div class="pane" data-pane="keys">
  <div class="field">
    <div class="field-label">快捷键</div>
    <div class="field-hint">
      点右边的键位框，然后<b>直接按下你想用的键</b>就改好了。<br>
```

> **列表由 JS 生成**（`id="keyList"` 里面是空的）：因为键位是可变的，写死在 HTML 里就得在 JS 里再对一遍名字，容易对不上。**一份清单，两处用**（见 §2.2）。

### 2.2 一份"动作清单"当唯一准绳

**这张表怎么用（三处，全从它来）**：

1. **画界面**：`#keyList` 里一行一个动作（动作名 + 一个键位框 + 一个「恢复默认」小按钮）。
2. **听键盘**：全局 `keydown` 里不再一条条写 `if (e.key === …)`，改成
   `const hit = matchKey(e); if (hit) { runKeyAction(hit); return; }` —— **顺序、按键全由表 + 存档决定**。
3. **写提示**：`title="查看歌词（Ctrl+D）"` 改成 `keyHint('toggleLyric')` 生成（见 §2.5）。

> 迟早会漏。改成表之后，"加一条快捷键"= 在表里加一行。

### 2.3 键位怎么存、怎么比

**存档格式**（`settings.keys`）：

```js
keys: {
  togglePlay: 'Space',
  prevTrack: 'Ctrl+ArrowLeft',
  …
}
```

- 键位写成**字符串**：修饰键用 `Ctrl+` / `Alt+` / `Shift+` 前缀，主键用 `KeyboardEvent.key` 的名字
  （`Space` / `ArrowLeft` / `d` / `F11` …）。`Ctrl+Shift+P` 这种也支持。
- **一个动作只存一个键**（不做"主键 + 备用键"两套，先用起来简单）。
- 存档里**只存和默认不一样的**（省事）：读的时候 `键位 = settings.keys[id] || 该动作的 def`。

**按下时怎么比**（关键：修饰键必须**完全一致**，不能"多按了 Shift 也算"）：

```js
/** 把一次按键规范化成 'Ctrl+Shift+P' 这种字符串；认不出来（纯修饰键）返回 null */
function keyFromEvent(e) {
  const k = normalizeKey(e.key);          // ' ' → 'Space'、大小写统一、'Esc' → 'Escape' …
  if (!k) return null;
  if (k === 'Control' || k === 'Shift' || k === 'Alt' || k === 'Meta') return null;  // 光按修饰键不算
  const parts = [];
  if (e.ctrlKey || e.metaKey) parts.push('Ctrl');   // macOS 上 Cmd 也算 Ctrl（和现在一致，app.js:2553）
  if (e.altKey)  parts.push('Alt');
  if (e.shiftKey) parts.push('Shift');
  parts.push(k);
  return parts.join('+');
}
```

> ⚠️ **一个必须处理的坑**：现在 `Ctrl+←` 那两条**故意没写 `preventDefault()` 之外的东西**，而 `←` 单独的
> 快退是写在**后面**的（`app.js:2589` 在 `:2609` 之前）—— 也就是**靠代码顺序**让 `Ctrl+←` 先命中。
> 改成表驱动之后，**顺序由表决定**，所以匹配时**必须"修饰键完全一致"**（上面 `keyFromEvent` 就是干这个的），
> 否则会出现"按 Ctrl+← 同时触发了上一首和快退 5 秒"。**这一条要专门写个断言守住。**

### 2.4 录制（点一下改键位）+ 冲突提示 + 恢复默认

**交互**：

```
点键位框  →  框变成「按下新键…」（高亮、呼吸）  →  按下新键  →  改好，框显示新键位
                        ↓ Esc / 点别处
                     取消，保持原样
```

**判定规则**（改键位时挡掉明显不合适的）：

| 情况 | 怎么处理 |
|---|---|
| 按了 `Esc` | **取消录制**（不改成 Esc）—— 和所有弹窗的习惯一致 |
| 按了纯修饰键（只按 Ctrl） | 忽略，继续等 |
| 想绑 `Esc` | **不允许** —— 它是所有面板的逃生键（§1.1），绑走了面板就关不掉了 |
| 想绑单独的字母 / 数字（不带 Ctrl/Alt） | **允许但会提示**（"建议加个 Ctrl，不然打字时会误触"）—— 因为 §1.2 那条"输入框里让路"已经挡住了大部分误触，不硬禁 |
| 这个键**已经被别的动作用了** | **不直接改**，弹一句"这个键已经是「下一首」在用，要先把它改掉吗？" —— 给两个选择：【换掉它】/【取消】 |
| 这个键**和某个动作的默认键**撞了（但那个动作已被改到别处） | 允许（没冲突） |

**恢复默认**：每个动作右边一个小按钮（↺）恢复这一条；页底一个「全部恢复默认」恢复全部。

### 2.5 界面上那两处写死的提示要跟着走

- `index.html:294` 的 `title="查看歌词（Ctrl+D）"` → 由 `app.js` 在启动时写上去（`keyHint('toggleLyric')`）。
- `index.html:333` 的 `title="歌词（Ctrl+L）"` → 同理。
- `app.js:3006` / `app.js:3027` 那两句动态提示里的 `（Ctrl+L）` / `（Ctrl+D）` 改成拼 `keyHint(...)`。

> 这样**改完键位，提示立刻就对**，不会出现"提示说 Ctrl+D、按下去没反应"。

### 2.6 全局 keydown 改造后的样子（骨架）

```js
document.addEventListener('keydown', (e) => {
  // ★ 这一条一个字都不改：输入框 / 文本域 / 下拉框里，快捷键一律让路
  if (isTypingTarget(e.target) && e.key !== 'Escape') return;

  // 正在录制键位？那这一下是"新键位"，不是"执行功能"
  if (recordingKeyAction) { captureKeyForRecording(e); return; }

  // 键位表命中 → 执行（找不到就是没绑，什么都不做）
  const key = keyFromEvent(e);
  if (!key) return;
  const hit = KEY_ACTIONS.find((a) => keyOf(a.id) === key);
  if (!hit) return;

  // Esc / F11 之类的特例仍然放行给原来那套逻辑（见下）
  e.preventDefault();
  runKeyAction(hit.id);
});
```

- `runKeyAction(id)` 就是**把现在那 10 段 if 里的动作体原样搬进来**（`togglePlay` / `next(±1)` / `applyVolume(…)` / `audio.currentTime ±5` / `toggleLyrics()` / `toggleDesktopLyric()` / 全屏）。
- **`F11` 全屏**和 **`Esc`** 保持"永远可用、不可改"（`Esc` 压根不进表；`F11` 进表但**默认值保留**，允许改走 —— 见 §5 Q3）。
- **不写 `e.preventDefault()` 的分支**：`Ctrl+L` / `Ctrl+D` 这种组合键要 preventDefault（否则 Chromium 有自己的默认行为）；
  `空格`、方向键**必须** preventDefault（否则页面会被滚下去，现在就是这么做的，`app.js:2582`）。

## 四、怎么验证（不靠"我觉得"）

### A. 静态自检（`.verify/verify.js`）

- `app.js` 里有 `KEY_ACTIONS` 且**至少 10 条**；每条都有 `id` / `name` / `def`
- `DEFAULT_SETTINGS.keys` 存在；`migrateSettings` 里补了 `keys`
- `index.html` 里有 `data-tab="keys"` 与 `data-pane="keys"`；`#keyList` 存在
- `KEY_ACTIONS` 里**没有** `Esc`（逃生键不许被绑走）
- `keyFromEvent` 里同时出现 `ctrlKey` 与 `shiftKey`/`altKey`（证明"修饰键参与比较"，不是只比主键）

### B. 离屏实测（`.verify/test-keys.js`，新建）

1. **页面能开**：点「快捷键」标签 → `.pane[data-pane="keys"]` 的 `display` 从 `none` 变 `block`，且 `#keyList` 里渲染出 **≥10 行**
2. **默认键位对**：每行的键位框文字 == 该动作的默认键（`播放 / 暂停` 那行显示 `空格`）
3. **改键生效**：点「播放 / 暂停」的键位框 → 派发 `keydown`（`Ctrl+P`）→
   `DB.settings.keys.togglePlay === 'Ctrl+P'`，且框里显示新键位
4. **改完真的能用**：再派发一次 `Ctrl+P`（不在录制态）→ 播放/暂停**真的被触发**（用桩掉的 `audio.play/pause` 计数验证）
5. **旧键位失效**：再派发 `空格` → **不再**触发播放/暂停
6. **修饰键完全一致**（§2.3 那个坑）：把「上一首」绑成 `Ctrl+ArrowLeft`、把「快退 5 秒」绑成 `ArrowLeft`，
   然后派发一次**带 Ctrl 的** `ArrowLeft` → **只**触发上一首，快退**计数为 0**
7. **冲突提示**：把「下一首」的框点开、按 `Ctrl+P`（已被「播放/暂停」占用）→ 出现冲突提示，且**没有**静默改掉
8. **Esc 取消录制**：点开键位框 → 按 `Esc` → 键位**保持原样**，录制态退出
9. **恢复默认**：点某行的 ↺ → 该动作回到默认键；点「全部恢复默认」→ `settings.keys` 变回 `{}`
10. **输入框让路**（回归 §1.2）：焦点在搜索框里派发 `空格` → **不**触发播放/暂停
11. **存档往返**：改完键位 → 触发一次存盘 → 用存回来的数据重新 `migrateSettings()` → 键位还在
12. **回归**：`test-playing.js` / `test-round8.js` / `test-round9.js` 继续全绿

### C. 真机（只能你做）

1. 设置 → 快捷键 → 看到 10 行，键位和现在用的一致（`Ctrl+L` / `Ctrl+D` / 空格 …）
2. 把「整页歌词」从 `Ctrl+D` 改成 `Ctrl+Shift+L` → 按新键能开歌词；按 `Ctrl+D` 不再有反应

4. 点一个键位框、按 `Esc` → 取消，没改掉
5. 把一个键改到已经被占用的键上 → 弹出"这个键已经被 XX 用了"
6. 改完之后**重启软件** → 键位还在（存档生效）
